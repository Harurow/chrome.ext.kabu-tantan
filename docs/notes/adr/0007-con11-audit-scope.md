# ADR-0007 他拡張のクラス混入をどこまで点検し、どう再発を止めるか

| | |
| --- | --- |
| 状態 | 採択（2026-08-23）。1.12.2 で実装（点検は 2026-08-23 に実施済み） |
| 対象 | CON-11（＋ FR-21, FR-03, CON-03, CON-09） |
| 仕様 | [SPEC-CS-21](../specs/content-scripts.md)（＋ SPEC-CS-09, SPEC-SC-12 廃止, SPEC-SC-16） |
| 発端 | `src/sbi-cs.js` のポートフォリオ用セレクタが `body.vsc-initialized` で始まっていた。SBI証券のクラスではなく **Video Speed Controller が `<body>` に付けるクラス**で、当該拡張を入れていない環境では最初から動いていなかった（`657f366` で混入、2026-08-23 に FR-12 の検証で確定） |

---

## 1. 点検の範囲

**決定: `src/*-cs.js` の `menuSelectors` に載る検出用セレクタ 20 件を1回だけ全点検する。CSS は対象外。**

| 案 | 判定 |
| --- | --- |
| (a) `body.vsc-initialized` だけ外して終わり | 却下。同種の混入が他にあるかを**誰も確認していない**状態が残る。20 件を読むだけなので、確認しないほうが不合理 |
| **(b) 採用** 検出用セレクタ 20 件を全点検し、以後は機械的ガードで守る | 点検は1回で終わり、以後の費用は `npm test` のみ。CON-09（個人開発）に見合う |
| (c) CSS のセレクタまで広げる | 却下。壊れても見た目が崩れるだけで機能は残る（FR-12 の検証対象と同じ線引き）。しかも `tradingview-cs.css` の `html.theme-dark` は**サイト側の正当なクラス**で、機械判定に掛ければ誤検知しか出ない（CON-03） |
| (d) 「拡張なしプロファイル」と突き合わせる検証をツールに足す | 却下。実行に2プロファイルが要り、ログインも2回になる。同じ欠陥は G1 が `npm test` で止められる（実サイトを見ずに済む） |

点検結果は SPEC-CS-21 の表。**混入は 1 件のみ**で、残り 19 件は楽天証券・SBI証券・
Refinitiv 製スクリーナー・React アプリ・TradingView それぞれの命名規則で一貫していた。

---

## 2. 再発を止める規則

**決定: 構造規則（G1）を主、名前の否定リスト（G2）を従にする。**

| 案 | 判定 |
| --- | --- |
| (a) 既知の他拡張クラスの否定リストだけ | 却下。拡張の数だけ名前があり**原理的に網羅できない**。次に混ざるクラスの名前は誰も知らない |
| **(b) 採用** G1「検出用セレクタは `body` / `html` を起点にしない」＋ G2「既知の他拡張クラスを含まない」 | 他拡張が印を付ける場所は `<body>` / `<html>` に集中する（CON-11）。**名前を知らなくても位置で弾ける。** G2 は既知の再混入を止める補助 |
| (c) 人のレビュー観点として文書に書くだけ | 却下。`657f366` の混入もレビュー不在ではなく**気づけなかった**ことが原因。機械で落ちるほうが確実 |

### G1 の副作用を承知で受け入れる

将来、サイト側が `<body>` に付けたクラスを検出条件に使いたくなるとテストが落ちる。
そのときはテストを1箇所直せばよい。**落ちること自体が「本当にサイト側のクラスか」を
確認する機会**になるので、むしろ望ましい。

対象5サイトの検出用セレクタは、いずれも `body` / `html` を起点にする必要が無い
（`div#main` / `div#line1` / `div#root` などページ内の器から始められる）。

---

## 3. FR-12 側の追加検査（SPEC-SC-12）をどうするか

**決定: 廃止する。**

| 案 | 判定 |
| --- | --- |
| (a) 残す | 却下。セレクタから当該クラスを外すと「セレクタが `body.vsc-initialized` で始まっていない」としか出力しなくなり、毎回の結果ファイルに無意味な節が残る |
| **(b) 採用** 廃止し、ID を欠番にする | 目的（白黒をつける）は 2026-08-23 の3回目の実行（3回目版 `git show e0d3c5e:docs/SELECTOR-CHECK.md` の「ポートフォリオの追加検査」節）で達成済み。再発防止は G1・G2 が引き継ぐ |
| (c) 汎用化して「他拡張クラス依存の自動検出」にする | 却下。実サイトで実行しないと分からない検査になり、ログインが要る。G1 は `npm test` で同じ欠陥を止められる。**安く確実なほうを採る** |

廃止にともない、利用者が居なくなる `result.extra` と「追加検査」節の生成も消す。
`target.extra === 'tv-symbol'`（TradingView の接頭辞検査）は `result.notes` に書くため影響しない。
