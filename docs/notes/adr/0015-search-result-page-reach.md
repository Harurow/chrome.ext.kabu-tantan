## 0. 何が起きていたか

| | ツールの観測 | 実際 |
| --- | --- | --- |
| `div#line1 h1.hdg-l1-01-title` | 0 件 | **存在する**（利用者の DevTools で確認） |
| 注入（`span.x-kabu-root`） | 0 件 | **注入されている**（`" オリンパス (7733)"` ＋ `ul.x-kabu-body`） |
| 手がかりの主要コンテナ | `div.pcm-header` / `div.pcm-content` | **検索前の画面のもの** |

**ツールはフォームを送信しない**（CON-10）。株価検索は**検索を実行して初めて結果画面になる**ため、
ツールが見ていたのは入力画面だった。**セレクタは一度も壊れていない。**

> **FR-23 と同じ型の誤りである。**
>
> | | 観測 | 立てた仮説 | 実際 |
> | --- | --- | --- | --- |
> | FR-23 | エラー画面に飛ばされる | 遷移元が要る → **リンクをたどる機構を作った** | **クエリが無かっただけ** |
> | FR-20 | セレクタが 0 件 | ページが刷新された → **破損** | **ツールが別の画面を見ていた** |
>
> どちらも**ツールの観測を、サイトの状態と読み違えている**。
> ADR-0011 の 13 で書いた教訓（原因を特定しないまま結論を出す）が、FR-20 にも当てはまっていた。

## 1. `?dscrCd=…` を付けて開くのは「検索の実行」か（CON-10 の解釈）

**決定: アドレスバーに出る GET の URL なら「対象ページの URL へ遷移する」に当たり、許容する。
フォームの送信でしか結果が出ないなら不可。**

CON-10 の許容行1 は「ログイン済みセッションで**対象ページの URL へ遷移する** ✓」、
禁止は「**検索条件の送信**・絞り込み」「フォーム送信」である。境界は次のように引く。

| 形 | 判断 | 理由 |
| --- | --- | --- |
| **結果画面が GET の URL を持つ**（アドレスバーに出る／ブックマークできる） | **許容。** その URL は**ページのアドレス**であって、開くことは遷移でしかない | サイト自身が「この URL はこのページ」と定義している。**利用者が手で開くのと同じ** |
| 結果がフォームの送信でしか出ない（アドレスバーが変わらない／POST） | **不可。** FR-15 の例外（人がタブを開く）へ回す | 送信は CON-10 の禁止そのもの。**実体が送信か遷移かを外から判別できない**（ADR-0011 の 3 と同じ理由） |

**先例がある。** 国内株式・個別銘柄は既に `?eventType=init&dscrCd=7203&…` で開いており、
何度も ✅ になっている。**「銘柄を指定してページを開く」ことは、既に遷移として扱ってきた。**
株価検索だけを「検索の実行」と読む理由は無い — **形が同じなら同じ扱いにする。**

> **逆に、スクリーナー2種を `tab` にしている理由もこれで説明できる。**
> あちらは結果一覧が**フォーム送信でしか出ない**ため、URL では到達できない（SPEC-SC-06）。
> **「URL で到達できるか」が境界**であって、「検索という語が付くか」ではない。

### 状態を変えないことの確認

GET で結果画面が出るとして、それが**サイト側の状態を変えない**とまで言えるか。

| 懸念 | 判断 |
| --- | --- |
| 閲覧履歴・検索履歴が記録される | **既に受け入れている。** 個別銘柄を `dscrCd` 付きで開く時点で同じことが起きる。ここで新たに越える線は無い |
| 銘柄コードを1つ固定で使う（`7203`） | 現行どおり。**銘柄を変えて回さない**（データの一括取得にしない。CON-10） |

## 2. どう決めるか（推測で進めない）

**ADR-0011 の教訓をそのまま適用する。実測を1回もらってから決める。**

| # | 手順 |
| --- | --- |
| 1 | **利用者に、検索実行後のアドレスバーの URL を1回だけ聞く**（セッション ID を除いて。FR-23 で4本もらったのと同じ形） |
| 2 | **GET の URL が出ていれば**、`targets.mjs` の株価検索のクエリを**実測どおりに写す**（SPEC-SC-06 の規則1。推測で削らない） |
| 3 | **URL が変わらない／POST なら**、FR-15 の「利用者がタブを開いておく例外」へ回す。**現在ゼロ件の例外を1つ作る**ことになるが、スクリーナー2種と同じ理由なので筋は通る |

**2 を先に試す。** 楽天証券の他13ページはすべてクエリで到達できており、
株価検索だけが例外である理由が今のところ無い。

> **「試す」の中身は実行ではなく質問である。** ツールを何回か回して当てにいくのではなく、
> **アドレスバーを1回見せてもらえば決まる**（ADR-0011 の 13 の教訓 2）。

### 却下した案

| 案 | 判定 |
| --- | --- |
| いますぐ FR-15 の例外へ回す | 却下。**GET で到達できるなら例外は不要**で、利用者の手順を恒久的に1つ増やすことになる。先に 2 を確かめる |
| 対象から外す（判定しない） | 却下 → **4 で採用**。当時の却下理由は「**FR-12 の対象は「12ページすべて」**と要件が決めている（間引かない）」「外すと、本当に壊れたときに気づけなくなる」。**前者は要件側が例外を明文化して前提が消えた**（分かれ目は「CON-10 を守るかぎり到達できないか」）。**後者は残るので、手動チェックリストの項目と `検証ツールの対象外` 53 で担保する** |
| クエリを推測して何度か試す | 却下。**ADR-0011 で3度繰り返した誤り。** 当て推量の再演 |
| フォームを送信する | 却下。CON-10 の禁止そのもの。**この却下は今も生きている**（「CON-10 の機械的な担保を置き直す」節。`セレクタ定義` 52 が機械で止める） |

> **却下の記録は消さない。** 2 の時点の判断としては正しく、
> **どの前提が消えたから覆ったのか**を残すほうが、次に同じ案を出したときに速い
> （ADR-0011 の 14「この ADR がいちばん価値を持つのは『やらなかったこと』の側である」と同じ扱い）。

## 3. 一般化: ツールが見ている画面 ≠ 利用者が見ている画面

**この誤りは株価検索に限らない。** 到達判定（SPEC-SC-24）は**題名が未到達の目印に当たらないか**しか見ず、
**「対象ページに着いた」ことまでは確かめていない**。FR-22 のときに承知のうえで受け入れた限界
（SPEC-SC-18「到達判定は『エラー画面ではない』ことしか示さない」）が、
**「同じページの別の状態」にも及ぶ**ことが今回分かった。

| 種類 | 例 | 気づき方 |
| --- | --- | --- |
| 別のページに着く | エラー画面・ログイン画面 | 題名の目印（SPEC-SC-24） |
| **同じページの別の状態に着く** | **検索前 / 検索後** | **題名では分からない。** ページ識別セレクタが結果側の要素なら 0 件になるが、**それは「破損」と同じ観測** |

**手当ては「気づける形にする」ことまでで、機械では分けられない。**
SPEC-SC-18 に限界として立て、**❌ を見たらまず利用者に実機を確かめてもらう**運用にする
（SPEC-SC-24 が既に「❌ を見たら手がかりの題名を人が読む」としているのを一段強める）。

> **ページ識別セレクタを「結果画面にしか無い要素」にすれば、⚠️（未到達）に倒せる**という手もある。
> 破損（❌）と未到達（⚠️）の意味は違うので、**そのほうが正しい**。
> ただし FR-22 の到達判定は「識別 0 件でも題名が正常なら ❌」と決めており、
> **識別セレクタを変えるだけでは ⚠️ にならない**。
> **結果画面に到達できるようになれば、この問題自体が消える**ので、まず 2 を試す。

## 4. 実測は POST だった。却下した案が採られた（2026-09-01）

**2 の手順どおり利用者にアドレスバーを聞いた。回答は「変わらないように見える」＝ POST。**
1 の分岐表は「フォームの送信でしか結果が出ないなら**不可**」なので、GET で到達する道は消えた。

そのうえで利用者から運用の判断が来た。

> **今動いているのでOK。今後確認する時は人で。**

**結果、1 で「不可なら FR-15 の例外（`reach: 'tab'`）へ」としていた行き先ではなく、
2 で私が却下した「対象から外す」が採られた。**

### 私の却下理由への回答

| 却下理由（2 で書いたもの） | 現在の答え |
| --- | --- |
| **FR-12 が「12ページすべて」を対象と決めている**（間引かない） | **要件側が例外を明記した。** 分かれ目は「**CON-10 を守るかぎり到達できないか**」であって「到達が難しいか」ではない。FR-23 の4ページは**難しかっただけで到達できた**（クエリを写せばよかった）。株価検索は**POST でしか結果が出ない＝到達できない**側で、例外に当たる |
| **本当に壊れたときに気づけない** | **残る。** 完全には埋まらない。担保は2つ。**(1)** 対象の定義・結果表の行・「検証したセレクタ」の表を**残す**（SPEC-SC-10 の 4）ので、**セレクタ値そのものは結果ファイルに出続ける**。**(2)** `docs/notes/manual-checklist.md` に人が見る項目を立てる |

**却下は当時の要件に照らせば正しく、要件が変わったことで前提が消えた。**
ADR-0011 の案 (a)（クエリを足す）と同じ型で、**却下理由が消えたら採り直す**。

### なぜ `reach: 'tab'` ではないのか（スクリーナー2種との一貫性）

スクリーナー2種も「フォーム送信でしか結果が出ない」ため URL で到達できないが、
**あちらは対象外にせず `reach: 'tab'` にしている**（FR-15 の例外）。扱いを分ける理由は**人の手順の重さ**。

| 対象 | 人がやること | ログインのついでにできるか |
| --- | --- | --- |
| スクリーナー2種 | 画面を開いて検索を実行し、**タブを開いたままにする** | **できる**（FR-15 が例外として明記済み。利用者が受け入れ済み） |
| 国内株式・株価検索 | 銘柄コードを**入力して検索ボタンを押す**まで人がやる | **ついででは終わらない** |

**費用の形が違う。** `tab` は**実行のたびに**費用が発生し、対象外は**確認したいときだけ**発生する。
「今動いているのでOK」という状態では、**毎回の費用のほうが高くつく**。

> **差し替えは容易にしてある。** `excluded` を消して `reach: 'tab'` と `frameUrl` を書けば戻る
> （`pageSelectors` / `query` は残してある。SPEC-SC-10 の 4）。
> **運用が変わって「毎回自動で見たい」となったら、そのとき切り替えればよい。**

### 教訓: 選択肢には「いつ費用が発生するか」を書く

**2 の却下表には、案ごとの費用が「増える/増えない」としか書いていなかった。**
`tab`（実行のたび）と対象外（確認したいときだけ）は、**総量ではなく発生の時点が違う**。
利用者はそこを見て選んだ。

> **「何ができるか」だけでなく「いつ費用が発生するか」まで書く。**
> 恒久的に毎回かかる小さな手間は、**必要なときだけかかる大きな手間より高くつくことがある**。
> 選択肢を並べるときは、**費用の総量ではなく発生の形**（毎回 / 必要時 / 一度きり）を明示する。

### 実装（1.19.0）

| 対象 | 内容 |
| --- | --- |
| 判定 | **第5状態 `EXCLUDED`（記号 `👤`）** を追加。総合判定の件数にも終了コードにも入れない（SPEC-SC-10 / SPEC-SC-15） |
| `targets.mjs` | 株価検索に `excluded`（理由の文字列）を持たせる。**`pageSelectors` / `query` は残す** |
| 結果ファイル | `👤 対象外` 列、「対象外の対象（人が確認する）」節、「判定の読み方」の行（SPEC-SC-13） |
| 自動テスト | `検証ツールの対象外` 3件 ＋ `結果ファイルの書式` 1件（SPEC-SC-16 の 47〜50） |

**`EXCLUDED` を ❌ / ⚠️ / — に混ぜないことが、この実装の要点である。**
混ぜると「判定できないもの」が**恒久的な異常表示**になり、人はそれを読み飛ばすようになる。
**それは ❌ を常態化させたのと同じ失敗**で、本当のやり残しが埋もれる。

### CON-10 の機械的な担保を置き直す

**株価検索を対象外にしたことで、「フォーム送信すれば取れる」という誘惑が残る。**
本 ADR 自身が却下案として「フォームを送信する」を挙げており、**次に触る人が最初に思いつく案**である。

1.19.0 で `links.mjs` を撤去したとき、そこにあった
**「クリック・フォーム送信を書かない」のソース検査（旧 40・41）も一緒に消えた**。
方式ごと消したので妥当だが、**CON-10 の中核を機械で守るものが無くなった**のは副作用である。

**決定: `check.mjs` に最小の構造テストを置き直す**（SPEC-SC-16 の `セレクタ定義` 52。**1.19.0 で実装**）。
**4条件とも、1つずつ壊して落ちることを実測した**（変異検証。SPEC-SC-16 の 52 の表）。
`.click(` はちょうど1件（`page.mouse.click(`＝ TradingView の右クリック。CON-10 の許容行）で、
`.submit(` / `requestSubmit` は現れない。

> **散文だけで守らない。** 「フォーム送信は行わない」は `targets.mjs` の `excluded` の理由文にも
> 本 ADR にも書いてあるが、**文章は実装を止めない**。
> 19・20（セレクタへの他拡張クラスの混入）と同じ形の、**安い機械的な歯止め**を置く。
