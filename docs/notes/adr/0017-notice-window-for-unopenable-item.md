# ADR-0017 右クリックメニューの項目を押しても開けないとき、小窓で知らせる

| | |
| --- | --- |
| 状態 | 採択（2026-10-11）。**1.21.0 で実装** |
| 対象 | FR-29（＋ FR-05, FR-08, FR-11, NFR-03） |
| 仕様 | [SPEC-SW-05 / SPEC-SW-10](../specs/service-worker.md) / [SPEC-NT](../specs/notice-page.md) / [SPEC-MF-03](../specs/manifest.md) |
| 発端 | 米国株のティッカーを選択し、米国株のページを持たない遷移先（22件中16件）を右クリックメニューで押すと、何も起きない。項目を出し分ける案は全サイトへの注入（権限の追加）が要り、2026-10-11 その5 で保留になった。同日その8 に利用者が「押したら開けないと知らせる。小窓で」を選んだ |

---

## 1. 何で知らせるか

**決定: 拡張のページを `chrome.windows.create({ type: 'popup' })` で開く（利用者が選んだ形）。**

| 案 | 判定 |
| --- | --- |
| **(a) 採用** 拡張のページを小さなポップアップウィンドウで開く | 権限が増えない（`chrome.windows` は権限不要）。Service Worker から開くので、押した元のページの種類（`chrome://`・ウェブストア・PDF）に左右されない（推測。元のページに何も入れないため）。別ウィンドウが開くぶん大げさ |
| (b) 押した元のページの中に出す（`activeTab` + `scripting`） | 却下（利用者が (a) を選んだ）。`chrome://` のページ・ウェブストア・PDF では注入できず、代わりの手段が要る |
| (c) Chrome の通知（`notifications`） | 却下（選択肢を示す前に外した）。「通知の表示」の権限警告が出て、更新で既存利用者に再承認が要る |
| (d) ツールバーのアイコンにバッジ（`action.setBadgeText`） | 却下。権限は要らないが、アイコンをツールバーに固定していない利用者には見えず、「押したのに反応しない」が直らない |
| (e) 通常のタブで拡張のページを開く（`tabs.create`） | 却下。タブが増え、開けたページと見分けにくい。利用者の選んだ「小窓」と違う |
| (f) Service Worker から `alert()` | 不可。Service Worker に `alert` は無い |

## 2. 小窓を1つに保つ方法

**決定: 開く前に、自分の小窓（ポップアップのうちタブの `pendingUrl ?? url` が `notice.html` で始まるもの）を `chrome.windows.getAll({ populate: true })` で探して閉じ、新しく開く。**

| 案 | 判定 |
| --- | --- |
| **(a) 採用** `windows.getAll` ＋ `pendingUrl` で探して閉じ、作り直す | 開いた直後（読み込み前）の小窓も拾える（SPEC-SW-10 の実測 2）。作り直すので、押した元のウィンドウの中央・前面に開き直せ、履歴も1件のまま。タブの URL を読むのは既存の `tabs` 権限で足りる |
| (b) 既存の小窓を使い回す（`tabs.update` で URL を変え、`windows.update` で前面へ） | 却下。利用者が動かした位置に残り、押した元のウィンドウから離れることがある。作り直しと比べて得が無い |
| (c) 小窓の ID を Service Worker のメモリに持つ | 却下。Service Worker は止まるとメモリを失い、止まった後に押すと2つ目が開く |
| (d) 小窓の ID を `chrome.storage.session` に持つ | 却下。`chrome.storage.onChanged` のハンドラは領域を見ずに右クリックメニューを作り直す（SPEC-SW-03）ので、押すたびに作り直しが走る。ハンドラに領域の判定を足すのは本件の範囲を超える |
| (e) `chrome.runtime.getContexts({ contextTypes: ['TAB'] })` で探す（権限不要） | 却下。開いた直後の小窓が返らなかった（SPEC-SW-10 の実測 3）。続けて押すと2つ目が開きうる |

- 続けて押す間隔が `windows.create` の完了より短いと2つ開きうる。右クリックメニューを開き直して押す操作はそれより遅いと見て、直列化は入れない（推測。実測していない）

## 3. 大きさと位置

**決定: 440×280（枠を含む）。押した元のウィンドウの中央に置く。元のウィンドウが分からなければ Chrome に任せる。**

- 位置を指定しないと画面の左上（0, 0）に開いた（SPEC-SW-10 の実測 4）。押した場所から離れる
- 大きさは、文言2行・開ける遷移先の一覧（既定の設定で6件・3行前後）・ボタンが収まる値。小さすぎる指定は Chrome が広げる（同 実測 5）
- `chrome.windows.get` は権限不要。元のウィンドウより小窓が大きいときは元の左上に寄せる（`Math.max(0, …)`）

## 4. 小窓に何を渡し、何を出すか

**決定: クエリに `reason` / `key` / `code` だけを渡す。遷移先の名前は小窓のページが `urls.js` から引く。選択文字列は渡さない。開ける遷移先の一覧を添える。**

| 案 | 判定 |
| --- | --- |
| **(a) 採用** クエリに識別子だけ（`reason` / `key` / `code`） | 値はすべて Service Worker が作ったもの（`code` は `getTickerCode` の結果で `[A-Z]{1,5}` など）。名前は小窓側で `externalUrlsMap` から引くので、表示する文字列をクエリに載せない |
| (b) 遷移先の名前や選択文字列をクエリに載せる | 却下。選択文字列は利用者が何を選んだか分からない（長い・私的な文でありうる）。ポップアップのアドレス欄に出る可能性もある（推測）。外部へは出ないが、出す理由が無い（NFR-03） |
| (c) `chrome.storage.session` に置いて小窓が読む | 却下。2 の (d) と同じ理由（作り直しが走る） |
| (d) 小窓が読み込んでから Service Worker にメッセージで問い合わせる | 却下。往復が増え、Service Worker が止まっていると遅れる。渡す値が小さいのでクエリで足りる |

- **開ける遷移先の一覧を添える**のは、FR-29 の困りごと「どの項目が開けるかは押してみるまで分からない」に、押した時点で答えるため。
  有効な遷移先のうち `url3` を持つものを設定の順に並べる（SPEC-NT-02）
- 文字列は `textContent` で入れる。クエリは利用者が書き換えられるので、HTML として解釈しない

## 5. 押されたときの処理を名前付き関数にする

**決定: `onClicked` のハンドラを `onContextMenuClickedAsync` としてトップレベルに置き、`addListener` にそのまま渡す。**

- Playwright からはブラウザ自身の右クリックメニューを押せない（1.21.0 の実装時に確かめた。ページに `contextmenu` は届くが `onClicked` は発火しない。CDP にも `chrome.contextMenus` にも代わりの手段が無い。SPEC-SW-10）。押した後の処理は、同じ関数を `serviceWorker.evaluate` で直接呼んで確かめる
  （SPEC-SW-02 の再構築テストと同じ書き方）
- 登録そのものは `chrome.contextMenus.onClicked.hasListener(onContextMenuClickedAsync)` で確かめられる。無名関数だとこれができない

## 5-2. 判定の順序を変えない

**決定: 銘柄コード → 識別子 → URL の順（1.20.3 と同じ）を保つ。**

- この順では、未知の識別子でも選択文字列が銘柄コードとして読めなければ `not-ticker` の小窓が開く（FR-29 の洗い出し 3 は「未知の識別子は知らせない」）
- 未知の識別子は利用者の操作では起きず（SPEC-SW-02）、`not-ticker` の小窓は遷移先の名前を出さないので、利用者に見える食い違いが無い
- 識別子を先に見る順に変えると 1.20.3 からの差分が増える。得るものが無いので変えない（1.21.0 の実装時に developer の指摘で明記した）

## 6. 版

**決定: 1.21.0（マイナー）。**

- 利用者に見える機能（小窓）を、既存の振る舞い（開ける場合）を変えずに足す。セマンティックバージョニングではマイナーに当たる。
  パッチ（1.20.4）は不具合の修正に使う
- 1.20.3（未アップロード）を先に出すか、まとめるかは決まっていないが、どちらでも本件を含む版は 1.21.0 になる

## 7. 銘柄コードと解釈できない文字列（2026-10-11 その9 に決着。1.21.0 で実装）

**決定: 知らせる。選択した文字列は小窓に出さず、渡さない（利用者が選択肢 (a) を選んだ）。**

旧版の判定基準 4 が「振る舞いを変えない」と決めていたため、architect は決めずに利用者に諮った。

| 案 | 判定 |
| --- | --- |
| **(a) 採用** 知らせる・選択した文字列は出さない | 右クリックメニューは文字を選べば必ず出るので、黙って抜ける場合の中でいちばん起きやすいと見ている（推測）。別のページは開かないので FR-08 の「開かない側に倒す」は保てる。選択文字列を渡さない理由は 4 の (b) と同じ |
| (b) 知らせる・選択した文字列の先頭を出す | 却下。選択文字列をクエリで渡すことになる（4 の (b)） |
| (c) 知らせない（旧版のまま） | 却下。「押したのに反応しない」が残る |

- 証券会社の項目で表示後にログインが切れた場合（FR-06 で確定済み。何も知らせない）は、小窓に揃えず対象外のままとした（利用者に伝え、異論なし）
