## NFR-03 利用者の情報を外部に出さない

- 個人情報・閲覧履歴・銘柄情報を収集・送信しないこと
- 拡張機能自身が外部ホストへリクエストしないこと
- 証券会社のセッション情報を保存・送信しないこと（URL 組み立てにのみ使い、都度破棄する）
- **証券会社のセッション情報およびそれを含む URL を、注入先ページの DOM と Content Script に渡さないこと**
  （2026-10-11 に明文化。楽天証券・内藤証券のどちらも対象。ログイン済みタブから組み立てた証券会社の URL は
  拡張機能のバックグラウンドの外に出さない）
- 遷移先は利用者の操作で開く場合のみ
- 外部リンクから遷移元情報が漏れないこと

**判定基準（4つ目の項目について）:**

1. 証券会社にログイン中の状態で TradingView の右クリックメニュー・「株Link」ボタンのメニューを開いたとき、
   注入先ページの DOM のどこにも証券会社の URL・セッション情報が現れないこと
   （属性値・テキスト・ツールチップを含む）
2. Content Script が受け取るメッセージの応答に、証券会社の URL・セッション情報が含まれないこと

| | |
| --- | --- |
| 優先度 | 必須 |
| 状態 | ✅ 外部リクエストゼロを自動テストで保証。全リンクに `rel="noopener noreferrer"`。**1.20.0 までは4つ目の項目に反していた**（TradingView の右クリックメニューの証券会社項目が、楽天証券のセッション ID 入り URL をリンクとして DOM に書き出し、Content Script も URL を受け取っていた）。**1.20.1 で是正した**（SPEC-MSG-06 / SPEC-CS-28 の自動テストで固定） |
| 仕様 | SPEC-OP-11, SPEC-CS-05, SPEC-EL-04, SPEC-SW-06, SPEC-MSG-06, SPEC-CS-28 |
| 関連 | CON-04, FR-06, FR-25（判定基準 5 の例外） |
| 経緯（2026-10-11） | 利用者報告で発覚。**本項は「保存・送信しない」とだけ書き、ページの DOM や Content Script へ渡すことを禁じていなかった。** DOM に載った URL は注入先サイトのページスクリプト・計測スクリプトから読めるため、実質的に第三者へ渡しうる。設計判断は ADR-0016。**この是正のために FR-25 判定基準 5 に例外を設けた**（証券会社項目では中クリック等が効かなくなる） |

## NFR-12 検証ツールが認証情報を残さない

- ログイン状態を次回の実行に持ち越さない（実行のたびに再ログインする前提とする）

## NFR-14 拡張機能の更新・再読み込み後に残った古いタブでサイトを乱さない ✅

拡張機能を更新・再読み込みすると、それ以前に開いていたタブの content script は
拡張機能本体と切り離される（この状態を以下「切断状態」と呼ぶ）。
**切断状態のタブでも、注入対象サイトの見た目と動作を乱さないこと。**

**困りごと（2026-08-23 実機確認）:** 開発中に拡張機能を再読み込みしたあと、
TradingView の古いタブでチャートを右クリックするたびに
「行が3つ増える → 拡張機能への問い合わせが失敗する → 3つとも消える」が繰り返され、
ホバーしても何も出ない死んだ行が一瞬見える。実害は小さいが、開発のたびに必ず踏む。

**判定基準:**

1. 切断状態のタブで、注入対象サイトを操作しても**コンソールに例外が出ない**こと
2. 切断状態のタブで、拡張機能が**要素を一切追加しない**こと
   （追加してから消す、も含めて行わない）
3. 正常時（切断していないとき）の挙動が変わらないこと
4. TradingView だけでなく、**拡張機能本体への問い合わせを行うすべての注入先**で 1〜3 を満たすこと
   （楽天証券・SBI証券のページも、問い合わせを行うなら対象）

**やらないこと:**

- 切断状態を検出して利用者に通知する（バナー・ダイアログ等）ことはしない。
  一般の利用者は拡張機能の更新直後に再読み込みすればよく、通知はかえって邪魔になる
- 切断状態から自動で復帰する（再注入・タブの再読み込み）ことはしない

> **なぜ要件にするか:** 一般の利用者もウェブストア経由の自動更新で同じ状態になる。
> 頻度は低いが、「サイトの DOM を勝手に触って壊さない」（NFR-01）の一部として扱う。
