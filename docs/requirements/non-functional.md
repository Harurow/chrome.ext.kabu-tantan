## NFR-01 注入対象サイトの動作を壊さない

拡張機能を入れた状態でも、注入対象サイトが本来の動作を保つこと。

- 対象要素が見つからない場合は DOM を一切変更しない
- 既存のイベントハンドラを壊さない（テキストノードのみを置換する）
- スクリプトエラーでサイト側の処理を止めない

| | |
| --- | --- |
| 優先度 | 必須 |
| 状態 | ✅ 1.12.0 で Service Worker への問い合わせをすべて try/catch で囲み、失敗しても例外を投げずに何もしない形にした（SPEC-CS-19）。TradingView は実サイトで例外 0 を確認済み（`docs/MANUAL-CHECKLIST.md` G-1 / G-2）。**据え置きの条件だった G-3 が 2026-08-24 に埋まった**（スクリーナーのタブで DevTools を開いたまま操作し、コンソール例外なし）。詳細は NFR-14 |
| 判断の但し書き（2026-08-25） | **G-3 の記録には「スクリーナーのタブ」としか書かれておらず、楽天スーパースクリーナーと SBI銘柄スクリーニングのどちらで実施したかが特定できていない**（G-3 の操作欄は「楽天スーパースクリーナー**または** SBI銘柄スクリーニング」）。したがって上記の ✅ は、**1系統での確認をもって楽天系・SBI系の両方を満たすと判断した推論**である。根拠は NFR-14 の判断と同じで、注入先 5 本が**同じ仕掛け**（SPEC-CS-19）であること。実施サイトが判明したら本欄に追記する |
| 仕様 | SPEC-CS-02, SPEC-CS-14, SPEC-CS-19 |
| 関連 | NFR-14（拡張機能の更新後に残った古いタブでの振る舞い） |

## NFR-12 検証ツールが認証情報を残さない

FR-12 の検証を実行しても、認証情報が開発者の端末に残らないこと。

- ログイン状態を次回の実行に持ち越さない（実行のたびに再ログインする前提とする）
- Cookie・ローカルストレージ・セッション情報がディスク上に残らないこと
- 検証結果の記録（FR-17）に、認証情報・Cookie・ページ本文を含めないこと
- 対象サイトのアカウント情報（ID・パスワード）をリポジトリにも設定ファイルにも置かないこと

**判定基準:** 実行後に、検証で作られたブラウザプロファイルがディスク上に存在しないこと。

> 毎回ログインし直すコストは利用者が受け入れている。
> 利便性より、認証情報を持たないこと（CON-04 と同じ方針）を優先する。

| | |
| --- | --- |
| 優先度 | 必須 |
| 状態 | ✅ 使い捨てプロファイルで実行し、正常終了・中断（SIGINT / SIGTERM）・stdin の終了のいずれでも破棄する。実行後に残っていないことをツール自身が検査する。実機で SIGTERM 後の残存ゼロを確認済み |
| 残件 | なし。実 TTY での Ctrl+C は 2026-08-23 に利用者の実端末で確認済み（Enter 待ちで停止 → Ctrl+C → 「中断しました（SIGINT）」、プロファイル・Chromium とも残存ゼロ） |
| 関連 | FR-12, FR-15, FR-17, CON-04 |

## NFR-14 拡張機能の更新・再読み込み後に残った古いタブでサイトを乱さない ✅

拡張機能を更新・再読み込みすると、それ以前に開いていたタブの content script は
拡張機能本体と切り離される（この状態を以下「切断状態」と呼ぶ）。
**切断状態のタブでも、注入対象サイトの見た目と動作を乱さないこと。**

**困りごと（2026-08-23 実機確認）:** 開発中に拡張機能を再読み込みしたあと、
TradingView の古いタブでチャートを右クリックするたびに
「行が3つ増える → 拡張機能への問い合わせが失敗する → 3つとも消える」が繰り返され、
ホバーしても何も出ない死んだ行が一瞬見える。実害は小さいが、開発のたびに必ず踏む。

**判定基準:**

1. 切断状態のタブで、注入対象サイトを操作しても**コンソールに例外が出ない**こと
2. 切断状態のタブで、拡張機能が**要素を一切追加しない**こと
   （追加してから消す、も含めて行わない）
3. 正常時（切断していないとき）の挙動が変わらないこと
4. TradingView だけでなく、**拡張機能本体への問い合わせを行うすべての注入先**で 1〜3 を満たすこと
   （楽天証券・SBI証券のページも、問い合わせを行うなら対象）

**やらないこと:**

- 切断状態を検出して利用者に通知する（バナー・ダイアログ等）ことはしない。
  一般の利用者は拡張機能の更新直後に再読み込みすればよく、通知はかえって邪魔になる
- 切断状態から自動で復帰する（再注入・タブの再読み込み）ことはしない

> **なぜ要件にするか:** 一般の利用者もウェブストア経由の自動更新で同じ状態になる。
> 頻度は低いが、「サイトの DOM を勝手に触って壊さない」（NFR-01）の一部として扱う。
