# 非機能要件

## NFR-01 注入対象サイトの動作を壊さない

拡張機能を入れた状態でも、注入対象サイトが本来の動作を保つこと。

- 対象要素が見つからない場合は DOM を一切変更しない
- 既存のイベントハンドラを壊さない（テキストノードのみを置換する）
- スクリプトエラーでサイト側の処理を止めない

| | |
| --- | --- |
| 優先度 | 必須 |
| 状態 | ⚠️ Service Worker 応答待ちに try/catch が無く、失敗時にメニュー構築が止まりうる（SPEC-MSG-05） |
| 仕様 | SPEC-CS-02, SPEC-CS-14 |

## NFR-03 利用者の情報を外部に出さない

- 個人情報・閲覧履歴・銘柄情報を収集・送信しないこと
- 拡張機能自身が外部ホストへリクエストしないこと
- 証券会社のセッション情報を保存・送信しないこと（URL 組み立てにのみ使い、都度破棄する）
- 遷移先は利用者の操作で開く場合のみ
- 外部リンクから遷移元情報が漏れないこと

| | |
| --- | --- |
| 優先度 | 必須 |
| 状態 | ✅ 外部リクエストゼロを自動テストで保証。全リンクに `rel="noopener noreferrer"` |
| 仕様 | SPEC-OP-11, SPEC-CS-05, SPEC-EL-04, SPEC-SW-06 |

## NFR-04 バージョン更新で既存利用者の環境を壊さない

- 保存済み設定の識別子を変更しない
- バージョン比較を誤らない（`1.9.21` と `1.10.0` の大小を正しく判定する）

| 優先度 | 必須 |
| 状態 | ✅ |
| 仕様 | SPEC-EL-02, SPEC-SW-04, SPEC-SW-09, SPEC-TC-02 |

## NFR-08 変更の影響を自動テストで検知できる

コードを変更したとき、既存の振る舞いが壊れたことを人手の確認前に検知できること。

- 拡張機能を実際にブラウザへ読み込んだ状態で検証すること
- 証券会社へのログインを必要としないこと
- 配布物そのものを検証できること

| | |
| --- | --- |
| 優先度 | 重要 |
| 状態 | ⚠️ 27テスト。**実サイトの DOM 変更は検出できない**（フィクスチャに対する検証のため）。TradingView は対象外（`docs/TESTING.md`, CON-08） |
| 仕様 | `docs/TESTING.md`, `docs/TEST-CATALOG.md` |
| 補完 | 自動テストで届かない「実サイトのセレクタが生きているか」は FR-12 の半自動検証で確認する。**この NFR の対象は自動テストのみ**であり、FR-12 の達成によって ⚠️ が ✅ になるわけではない |

## NFR-12 検証ツールが認証情報を残さない

FR-12 の検証を実行しても、認証情報が開発者の端末に残らないこと。

- ログイン状態を次回の実行に持ち越さない（実行のたびに再ログインする前提とする）
- Cookie・ローカルストレージ・セッション情報がディスク上に残らないこと
- 検証結果の記録（FR-17）に、認証情報・Cookie・ページ本文を含めないこと
- 対象サイトのアカウント情報（ID・パスワード）をリポジトリにも設定ファイルにも置かないこと

**判定基準:** 実行後に、検証で作られたブラウザプロファイルがディスク上に存在しないこと。

> 毎回ログインし直すコストは利用者が受け入れている。
> 利便性より、認証情報を持たないこと（CON-04 と同じ方針）を優先する。

| | |
| --- | --- |
| 優先度 | 必須 |
| 状態 | ✅ 使い捨てプロファイルで実行し、正常終了・中断（SIGINT / SIGTERM）・stdin の終了のいずれでも破棄する。実行後に残っていないことをツール自身が検査する。実機で SIGTERM 後の残存ゼロを確認済み |
| 残件 | なし。実 TTY での Ctrl+C は 2026-08-23 に利用者の実端末で確認済み（Enter 待ちで停止 → Ctrl+C → 「中断しました（SIGINT）」、プロファイル・Chromium とも残存ゼロ） |
| 関連 | FR-12, FR-15, FR-17, CON-04 |

## NFR-13 検証対象のセレクタ定義が実装と乖離しない

FR-12 の検証対象セレクタが、拡張機能の実装と二重管理にならないこと。

**判定基準:** 拡張機能側の検出用セレクタを変更したとき、
検証側に同じセレクタ文字列を書き写す作業が発生しないこと。

> 二重管理すると、実装を直しても検証側が古いままになり、
> 「検証は通るが実際は壊れている」状態を作る。CON-08 で自動テストを見送ったのと同じ失敗。

| | |
| --- | --- |
| 優先度 | 重要 |
| 状態 | ✅ 検証ツールは検出用セレクタを持たず、拡張機能側の定義を読み取る。ツール側にセレクタが書かれていないことは自動テストで機械的に検査している |
| 関連 | FR-12, CON-09 |
