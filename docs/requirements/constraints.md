# 制約条件

要件を満たすうえで前提として受け入れている条件。**変えられないもの**と
**意図的に選んだもの**が混在する。後者は理由を明記する。

---

## CON-01 Manifest V3 で作る

Chrome ウェブストアは Manifest V2 の新規受付を終了している。V3 に従う。

派生する制約:

- バックグラウンドは永続プロセスではなく Service Worker。**いつでも休止しうる**
- `window` / `document` はバックグラウンドで使えない
- リモートコードの実行が禁止されている

| | |
| --- | --- |
| 種別 | 変えられない（プラットフォーム都合） |
| 仕様 | SPEC-MF-01, SPEC-MF-05 |

## CON-02 ビルドステップを持たない

`src/` をそのまま拡張機能として読み込める状態を保つ。

**理由:** 個人開発でメンテナンス頻度が低い。ビルドツールは数年放置すると
それ自体が動かなくなり、修正のたびに環境構築からやり直しになる。
ソースがそのまま動くことを優先する。

派生する制約:

- `import` / `export` が使えない
- スクリプト間の値の共有は `manifest.json` の `js` 配列の読み込み順に依存する
- TypeScript を使わない
- 同梱ライブラリはビルド済みファイルをそのまま置く

代償として、読み込み順の破損を検出する仕組み（`npm run validate`）が必要になる。

| --- | --- |
| 種別 | 意図的な選択 |
| 仕様 | SPEC-MF-06, SPEC-SW-01, SPEC-OP-02 |

## CON-03 他社が作ったサイトの DOM を書き換える

楽天証券・SBI証券・TradingView はいずれも**こちらの都合では変わらない**。

派生する制約:

- セレクタはサイト改修で予告なく壊れる。壊れる前提で設計する
- CSS セレクタに**サイト側で定義済みのクラス**が混ざる。
  リポジトリを grep して未使用に見えても、消すと壊れる場合がある
- 注入した要素がサイト側のスタイルに影響されうる
- サイト側の利用規約に反する操作をしない（データの自動取得・改変・自動売買はしない）

削除判定の手順は `AGENTS.md`「CSS を消すときの鉄則」に定める。

> DOM に見えるクラスがすべてサイト側のものとは限らない。**他の拡張機能が付けたクラス**を
> サイト側のものと誤認するリスクは CON-11 で扱う。

| 種別 | 変えられない |
| 仕様 | SPEC-CS 全般, SPEC-MF-07, SPEC-CS-13 |
| 関連 | CON-11 |

## CON-04 証券会社のセッションは借用しかできない

拡張機能が証券会社にログインすることはしない。
利用者が既に開いているログイン済みタブの URL からセッション情報を読むだけ。

派生する制約:

- `tabs` 権限が必要になる（**全タブの URL を読める強い権限**）
- ログイン済みタブが無ければ機能を提供できない
- セッション ID の URL 埋め込み形式が変わると壊れる

## CON-05 保存済み設定の識別子を変更できない

`chrome.storage.sync` に保存済みの識別子を変えると、既存利用者の設定が失われる。
一度公開した識別子は変更しない。

現状の識別子は命名が揺れている（`ullet/`、`karauri.net/` 等）が、**修正できない**。

## CON-06 同梱ライブラリのメジャー更新に追随する必要がある

セキュリティ上の理由で同梱ライブラリを更新すると、破壊的変更を受ける。

実績:

- Materialize 1.0 → 2.x で `.row` が CSS Grid 化し `.col` が廃止された。
  `.sN` が `.row` の直接の子でないと効かなくなった
- Materialize 2.x で `waves-effect` が削除された
- Material Icons のリガチャは `liga` ではなく `rlig`

| 種別 | 変えられない（上流都合） |
| 仕様 | SPEC-OP-04, SPEC-OP-12, `docs/ARCHITECTURE.md` |

## CON-07 外部リソースを実行時に取得しない

フォント・アイコン・画像・スクリプトはすべて `src/` に同梱する。

**理由:**

1. Chrome ウェブストアの審査でリモートコードは問題になる
2. 外部リクエストは利用者の情報を第三者に渡すことになる
3. 外部サービスが落ちると拡張機能が壊れる

代償として配布物のサイズが増える（Material Icons をサブセット化して緩和）。

| 仕様 | SPEC-OP-11, SPEC-OP-12 |

## CON-08 フィクスチャに対する自動テストを、実サイトの生存の根拠にしない

**2026-08-30 に改訂した（利用者承認）。改訂前の題は「TradingView はフィクスチャによる自動テストができない」。**
**緩和にあたる。** 経緯と、緩和したときの代償は本節末の「改訂の経緯」に残す。

TradingView の DOM はハッシュ付きクラス名（`menu-Tx5xMZww`、`item-GJX1EXhk` 等）で
構成され、リリースごとに変わる。フィクスチャを作っても実サイトとの乖離を検出できず、
**「テストは通るが実際は壊れている」状態になる。**

**ここから導けるのは「実サイトの生存の根拠にできない」までであって、
「フィクスチャを作ってはいけない」ではない。** 乖離の検出と、
**自分たちのコードの退行**の検出は別の目的である。

| 手段 | 目的 | 可否 | 根拠 |
| --- | --- | --- | --- |
| フィクスチャに対する自動テスト | **実サイトのセレクタが生きていることの判定** | ✗ | 実サイトとの乖離を検出できない |
| フィクスチャに対する自動テスト | **自分たちのコードの退行の検出** | **✓（下記の条件付き）** | 拡張が自分で生成した DOM の振る舞いは、サイト側の都合では変わらない |
| 実サイトに対する半自動検証（FR-12） | 実サイトのセレクタが生きていることの判定 | ✓ | 実物を見るので乖離が起きない |
| 人の目による確認（`docs/MANUAL-CHECKLIST.md`） | 見た目の妥当性・サイト側の挙動 | ✓ | 機械で判定できない |

**この制約が禁じているのは「実サイトを見ない検証を、実サイトの根拠として使うこと」であって、
実サイトを見る検証も、退行検出のためのフィクスチャも禁じていない。**

**フィクスチャを作ってよい条件（3つすべてを満たすこと）:**

1. **ハッシュ付きクラス名をフィクスチャに含めない。** 再現してよいのは、
   拡張が依存すると宣言している構造（セレクタ定義・属性名）だけとする
2. **サイト改修のたびにフィクスチャを更新する必要が生じないこと**（CON-09）
3. **自動テストが通ったことを、実サイトが壊れていない根拠として書かない・読まないこと**

> **条件 1 が全体を支えている。** 実 DOM を写し取ったフィクスチャは毎リリース腐り、
> **腐ったことに気づけない**（それが改訂前の結論の根拠だった）。
> 契約だけを再現すれば、サイト改修時にフィクスチャの更新が要らない。更新が要らないなら腐らない。

同じ理由から、楽天証券・SBI証券のフィクスチャによる自動テストも
**「実サイトのセレクタが生きている」ことの根拠にはならない**（この結論は改訂前から変わらない）。
一方でそれらは**現に自分たちのコードの退行を捕まえている**
（FR-13 の「遅れて現れた銘柄コード」3 件、FR-25 の「メニュー項目のクリック範囲」3 件）。
**改訂前の CON-08 は、その事実と整合していなかった。**

**改訂の経緯（2026-08-30）:**

| | |

| 発端 | 利用者の要望「早く自動できるようにしてください」（FR-26） |

## CON-10 検証のために対象サイトへ自動的・反復的にアクセスしない

FR-12 の検証は、**開発者が手元で明示的に起動したときだけ**対象サイトにアクセスする。

- 定期実行しない（CI・スケジューラから起動しない。`npm run check` にも含めない）
- **ログイン操作を自動化しない**（利用者が自分でログインする）
- ページの内容を取得・保存しない。セレクタがヒットするかを見るだけ
- 銘柄データの収集・注文操作は一切しない

**許容する自動操作（上記の例外）:**

| 操作 | 可否 | 理由 |
| --- | --- | --- |
| ログイン済みセッションで対象ページの URL へ遷移する | ✓ | 利用者が手で開くのと同じ操作。12ページを手作業で回るのは現実的でない |
| **対象ページへ移動するために、サイト内のナビゲーションリンクをクリックする** | ✓ | URL を直接開くのと同じ画面遷移。**リンクのクリックは「送信」ではない**（2026-08-24 に整理。FR-23） |
| TradingView の銘柄を切り替える | ✓ | 同上 |
| TradingView のチャート上で右クリックしてメニューを開く | ✓ | このメニューは開かないと DOM に存在せず、検証できないため |
| **株リンクが注入したメニューの項目**を選択する・外部サイトへ遷移する | ✗ | 検証に不要。検証対象でない第三者サイトへアクセスが波及する |
| サイト側の状態が変わる操作（検索条件の送信・絞り込み・注文・設定変更） | ✗ | サイト側の利用規約に触れる |
| フォーム送信・注文操作・データの一括取得 | ✗ | 同上 |
| **本表の許容行に無い操作**（**ナビゲーション以外の**メニュー項目の選択・タブの切り替え・並び替え・表示件数の変更・設定変更等を含む） | ✗ | 下記「最小性の原則」。**許容行に当たるものは許容行が優先する**（対象ページへ移動するためのナビゲーションリンクのクリックは、それがサイト自身のグローバルメニュー内の項目であっても許容行に当たる。FR-23） |

**最小性の原則（一般条項）:**

**検証に不要な操作はしない。** 自動で行ってよいのは本表の許容行（✓）に挙げたものだけとする。
表に無い操作は、**「サイト側の状態を変えないから」という理由だけでは許容しない。**
新たに必要になったら、**先に本表へ行を足し、理由を書いてから**行う。

> **なぜ一般条項を置くか:** 境界を「サイト側の状態を変えるか」だけにすると、
> 次に検証範囲を広げるときに「状態を変えないから可」で無制限に通ってしまう。
> 状態を変えないことは**必要条件であって十分条件ではない**。

**リンクのクリックを許容する条件（FR-23 判定基準 5）:**

**本節が条件の正本。** FR-23 判定基準 5 は本節を参照するだけで、条件を再掲しない
（2026-08-25 に二重管理を解消）。条件を足す・狭めるときは本節を直す。

- たどるのは対象ページへ移動するためのナビゲーションに限る
- クリックによってサイト側の状態が変わらないこと
- 遷移先は FR-12 の検証対象ページに限る（外部サイトへ出ない）
- **素の `<a href="...">` を左クリックして起きる GET 遷移に限る**
- **遷移先が対象ページであることを、URL のパスだけで判断しないこと**
  （2026-08-29 追加。下記「パス一致だけでは足りない」）

> 境界は「サイト側の状態を変えるか」で引く。ただし**それだけでは機械的に守れない**ため、
> たどってよい対象を「素の `<a href>` の GET 遷移」に限定する。
> `onclick` などの JavaScript ハンドラで遷移するもの（内部で `form.submit()` する、
> `fetch` / XHR で POST する等）は、**画面遷移が目的に見えても採らない。**
> 実体が「遷移」か「送信」かを外から判別できず、判断がつかないものは採らないため。
>
> **実装はクリックしない**（2026-08-29 追記 → 2026-09-01 更新）。
> ナビゲーションの到達は `page.goto()` だけで行う（TradingView の銘柄切り替えは専用の検索 UI を使う。2026-10-17〜、SPEC-SC-11）。`page.goto()` は常に GET なので、
> **ナビゲーションで POST・フォーム送信が起きる経路が実装上存在しない。**
>
> **上の条件より狭い。** 本節の許容そのものは変えない（将来クリックが必要になったときの正本として残す）が、
> **「もう押しているのだから押してよい」という読み方はできない。** 現時点でクリックの実績は無い。
>
> **2026-09-01: 機械的な担保が1つ消えた。**
> 本欄は 2026-08-29 から 2026-09-01 まで
> 「`scripts/selector-check/links.mjs` にクリック・送信の呼び出しが無いことを**自動テストが固定している**」と
> 書いていた。**1.19.0（`FR-30`）でリンクをたどる機構ごと撤去され、そのファイルもテストも無くなった。**
> **根拠として書いてあったものが消えたので、本欄からも消した。**
>
> **いま本節を守っているのは、実装の形（ナビゲーションは `page.goto()`、銘柄切り替えは TradingView の専用 UI）と散文である。**
> **機械的な担保を置き直すかどうかは設計側の判断**だが、**要件側からは2つ求める。**
>
> | # | 求めること |
> | --- | --- |
> | 1 | **置かないと決めるなら、その旨を `docs/specs/` に明記すること。** 黙って消えた状態にしない。**「かつては自動テストがあった」と読める記述を、実体が無いまま残さない** |
> | 2 | **本欄のように「自動テストが固定している」と書くときは、消えたら本欄も直すこと。** 根拠を他所のファイルに置く記述は、**そのファイルが消えた瞬間に空手形になる** |
>
> **リスクは下がっていない。むしろ上がった。** 1.19.0 で検証対象から外したのは
> **楽天証券・株価検索**で（`FR-30`）、**これはフォーム送信でしか結果画面に行けないページ**である。
> **つまり「対象に戻したい」と思ったときに、真っ先にフォーム送信を実装したくなる場所が、
> 検証対象の外に置かれた。** `docs/MANUAL-CHECKLIST.md` の C-1b が
> 「自動化を試みないでください」と書いているが、**それは散文であって歯止めではない。**

**パス一致だけでは足りない（2026-08-29 に条件を1つ追加）:**

FR-23 の実装レビューで、**遷移先の判定が URL のパスだけを見ており、
同一パス上にある操作用リンクを踏みうる**ことが分かった（実装は修正済み）。

| | |
| --- | --- |
| なぜ条件2 を満たさないか | 削除・編集・並び替えなどの操作が、**対象ページと同じパスにクエリ文字列だけで載っている**ことがある。パスが一致しても、それが「対象ページを表示するリンク」だとは限らない |
| なぜ機械的に効くか | 「素の `a href` の GET 遷移か」は DOM から判定できるが、「そのリンクを押すとサイト側の状態が変わるか」は**押してみないと分からない**。パスに加えてクエリまで見て**対象ページそのものだと確かめられた場合にだけ**たどる、という形にしないと条件2 を守れない |
| 一般化 | **遷移先の同一性は、その URL で実際に区別されている単位で判断する。** 楽天証券はセッションをパスパラメータに、操作をクエリに載せていたが、サイトごとに違いうる |

> **これは条件の追加であって、緩和ではない。** 既存の条件2（サイト側の状態が変わらないこと）を

## CON-11 セレクタに他の拡張機能が付与するクラスを使わない

注入対象サイトの DOM には、**利用者が入れている別の Chrome 拡張機能が付けたクラス**が
混ざっていることがある。セレクタはサイト側が出力するものだけを使う。

**実績:** `src/sbi-cs.js` のポートフォリオ用セレクタが `body.vsc-initialized` で始まっていた。
これは SBI証券のクラスではなく、**Video Speed Controller が `<body>` に付けるクラス**だった
（`657f366`）。当該拡張を入れていない環境では常に 0 件となり、
ポートフォリオでメニューが出ない状態が続いていた（FR-21）。
**1.12.2 で当該クラスをセレクタから除去し、同種の混入を止めるガードを入れた。**
あわせて検出用セレクタ 20 件を全点検し、**混入は当該 1 件だけ**と確認した
（[ADR-0007](../adr/0007-con11-audit-scope.md)）。

派生する制約:

- 実 DOM を見てセレクタを起こすときは、**その環境に入っている他の拡張機能の影響を疑う**
- `body` / `html` に付いたクラスは特に疑わしい（多くの拡張が印を付ける場所）
- 動作確認は、**株リンクだけを入れた Chrome** でも行う

> CON-03 は「サイト側のクラスを消してはいけない」と定めている。CON-11 はその裏返しで、
> **サイト側のクラスだと思ったものが実は他の拡張のものだった**というリスクを扱う。
> 「grep して使われていないから消す」も「実 DOM にあるから使う」も、
> どちらも根拠として不十分になりうる。

判定手順（何をもって「サイト側のもの」と見なすか）は仕様側で定める。

**再発防止の判定基準:**

1. 検出用セレクタの定義から、他の拡張機能が付けたクラスへの依存が機械的に検出されること
   （実サイトを見ずに、自動テストだけで止まること）
2. 判定基準 1 の検査が、既知の混入（`body.vsc-initialized`）を戻すと必ず失敗すること

> 判定基準 2 は 1.12.2 で developer が実際に戻して確認済み（3 本のテストが落ちた）。
