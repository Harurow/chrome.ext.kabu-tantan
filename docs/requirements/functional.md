## FR-04 TradingView から遷移先サイトを開ける

TradingView のチャート画面で、表示中の銘柄について遷移先サイトを開けること。

- チャートの右クリックメニューに項目を追加する
- **右クリックメニューの拡張は、チャート領域上で右クリックしたときに限る。**
  ウォッチリスト・ツールバー・銘柄検索など、チャート以外を右クリックしても項目を追加しない
  （表示中の銘柄と無関係な場所で、その銘柄のリンクを出さないため）
- ツールバーに専用ボタンを置き、そこからも開ける
- 銘柄コードが取得できないときはボタンを出さない

> **FR-19 との関係（2026-08-23 追記）:** 上記の「チャート以外を右クリックしても項目を追加しない」は、
> FR-19（ウォッチリストの行からの起動）で**部分的に緩める**提案が出ている。
> 緩めるのはウォッチリストの銘柄行に限り、かつ「右クリックしたその行の銘柄を出す」ことが条件。
> **表示中チャートの銘柄を他の場所で出さない**という本条の目的自体は変えない。FR-19 が未着手のあいだ、本条はそのまま有効。

**修正履歴（2026-08-23 判明 → 同日修正）:**

FR-12 の検証（`docs/SELECTOR-CHECK.md`）の初回実行で、TradingView の検出用セレクタ
4対象のうち2対象が**実サイトでヒット 0 件**だった。

| ヒット 0 件だった対象 | 検証で分かっていること |
| --- | --- |
| ツールバーへの挿入先（「株Link」ボタンの置き場） | 検出用セレクタのヒットが 0 件。ページ自体には到達している |
| 右クリックメニュー | 検出用セレクタのヒットが 0 件。右クリックでメニューは開いている |

チャート本体とオーバーレイレイヤーの検出は正常だったが、**拡張機能が実際に注入した要素は
どの対象でも 0 件**だった。**現在の TradingView では「株Link」ボタンも右クリックメニューの
追加項目も出ていない可能性が高い**（目視確認は未実施）。

**この検証で分かるのはヒット件数までで、なぜ 0 件なのかは分からない。**
実 DOM は未確認であり、原因の特定は修正タスクで行う。

> 別途 developer が手動で調べた範囲（2026-08-23）では、依存しているクラス名が変わり、

> 正式な確認は修正タスクで行う。**

拡張機能側のセレクタ値と判定結果は `docs/SELECTOR-CHECK.md` にある。

修正内容: 検出用セレクタ2値の差し替え、銘柄取得を canvas 経路に統一、
チャート領域上の右クリックに限る起点判定を追加（SPEC-CS-11 / 12 / 15 / 16、ADR-0002）。

## FR-07 遷移先サイトを定義で管理できる

遷移先サイトは1箇所の定義で管理し、追加・削除がそこだけで完結すること。

- 銘柄コードを URL に埋め込めること
- 国内株と米国株で異なる URL 形式に対応できること
- 米国株に対応しないサイトは米国株のメニューに出さないこと

**判定基準（TradingView の「株Link」ボタンメニュー、2026-08-23 追加）:**

不整合が残っているのはボタンメニューだけなので、判定基準はここに限って書く。

1. 米国株を表示しているとき、**米国株用の URL 形式を持たないサイトがボタンメニューに出ない**こと。
   「出るがクリックしても何も開かない項目」が 0 件であること
2. 国内株を表示しているときに出る項目は、現行と同じ一覧であること
   （米国株向けの絞り込みで国内株の項目が減らない）
3. 項目の並び順が、オプションページで設定した並び順（FR-09）と一致すること
4. 同じ銘柄について、ボタンメニューの情報サイト項目が、
   右クリックメニュー（FR-18）の入れ子に出る情報サイト項目と**同じ集合・同じ順序**であること

**やらないこと:**

- 証券会社の項目（FR-06）をボタンメニューに追加する／削るといった変更はしない。現行のまま
- ボタンメニューの見た目・開閉の作りは変えない（FR-18 のような入れ子化はスコープ外）

## FR-12 実サイトに対してセレクタの生存を判定できる

注入対象サイトの改修で**検出用セレクタ**が効かなくなったことを、
利用者からの報告を待たずに、開発者が任意のタイミングで確認できること。

**検証対象（検出用セレクタ）** — 壊れると機能そのものが消えるもの:

| サイト | 対象 |
| --- | --- |
| 楽天証券 | 銘柄コードを含む要素を探すセレクタ。**お気に入り〜株価検索の12ページすべて** |
| 楽天スーパースクリーナー | 結果一覧の銘柄コード要素を探すセレクタ |
| SBI証券 | 個別銘柄・ポートフォリオの銘柄コード要素を探すセレクタ |
| SBI銘柄スクリーニング | 結果一覧の銘柄コード要素を探すセレクタ |
| TradingView | チャート本体の検出、ツールバーへの挿入先の検出、右クリックメニューの検出 |

> 楽天証券は同一セレクタを使うページが複数あるが、**間引かない**。
> セレクタが同じでもサイト側の DOM は個別に改修されうる。

**検証対象外（模倣用クラス）** — 壊れても見た目が崩れるだけのもの:

- 拡張機能が見た目を合わせるために自分で付与するクラス（TradingView のメニュー項目・区切り線など）
- これらは人の目で確認する（`docs/MANUAL-CHECKLIST.md` A-9）

**判定基準:**

1. 検証対象のセレクタごとに「対象ページでヒットした要素数」を出力すること
2. 各対象ページについて、以下の3状態を区別できること

   | ページ自体を識別する手がかり | 銘柄要素のセレクタ | 判定 |
   | --- | --- | --- |
   | ヒットする | 1件以上 | **正常** |
   | ヒットする | 0件 | **破損**（サイト改修でセレクタが効かなくなった） |
   | ヒットしない | — | **ページを開けていない／ページ構造そのものが変わった** |

   > 「保有銘柄が無いので0件」と「セレクタが壊れて0件」を取り違えないための区別。
   > 実現手段（実装側のセレクタ定義に何を持たせるか）は設計側で決める。

3. 「破損」が 1 つでもあれば、成功と失敗を機械的に区別できること
   （終了コード等、目視によらない手段で区別できること）
4. どのサイトのどのページのどのセレクタが破損したかが、出力だけで特定できること
5. **「破損」または「ページを開けていない」と判定した対象について、
   原因の切り分けに使える手がかりを結果に残すこと**（2026-08-23 追加）

   目的は、次の3つを**結果ファイルを読むだけで**区別できるようにすること。

   | 疑うこと | 手がかりの例 |
   | --- | --- |
   | ページの URL が変わった | 到達先の題名が対象ページと別物 |
   | ログイン画面・エラー画面に飛ばされた | 到達先の題名がログイン系、見出しの構造が対象ページと違う |
   | 描画待ちが足りず、判定時点でまだ中身が無い | 題名は対象ページだが、主要コンテナが見当たらない |

   **残すもの:**

   | 内容 | 粒度 |
   | --- | --- |
   | 到達先ページの題名（`title` 要素の文字列） | そのまま |
   | 見出し要素（`h1`〜`h3`） | **タグ名・`id`・`class` 名のみ** |
   | 主要コンテナ | **タグ名・`id`・`class` 名のみ** |

   **残してはいけないもの:**

   | 内容 | 理由 |
   | --- | --- |
   | 要素のテキスト（題名を除く） | 銘柄名・保有状況などページ本文が混ざる（CON-10） |
   | URL・クエリ文字列・セッション ID | 認証情報を記録に残さない（NFR-12） |
   | HTML そのもの・スクリーンショット・Cookie | ページ内容を保存しない（CON-10, NFR-12） |

   > 題名は「どのページに着いたか」を人が読んで判断するための唯一の本文テキストとして許す。
   > ただし題名にセッション ID・URL が含まれている場合は記録しない。
   > 「主要コンテナ」として具体的に何を拾うかは設計側で決めてよいが、
   > **拾う対象を増やすほど本文が漏れる危険が上がる**ことを前提に、最小限にとどめる。

**対象の優先順位:**

TradingView を主対象、楽天証券・SBI証券を従とする。
TradingView の検証対象が判定できていれば、楽天証券・SBI証券は後から追加してよい。

> 根拠: `tradingview-cs.js` はハッシュ付きクラス名に依存しており、
> サイト改修で壊れる頻度が楽天証券・SBI証券より高い。

**SBI証券ポートフォリオの扱い:**

セレクタが `body.vsc-initialized` に依存している既知の課題（FR-03 ⚠️）について、
**この検証で白黒をつける**。実サイトで当該クラスが付与されているかどうかも結果に含めること。

**やらないこと:**

- ページの内容（HTML・スクリーンショット・銘柄データ）を保存しない（CON-03）
- 定期実行・CI での実行はしない。`npm run check` にも含めない（CON-10）
- 模倣用クラスの見た目の一致は判定しない
- 拡張機能本体（`src/`）に検証専用のコードを持ち込まない。
  検証のためにビルドステップを増やさない（CON-02）

## FR-15 1回の実行で全対象サイトを検証し終えられる

FR-12 の検証を、**1回の実行で最後まで通せる**こと。

- ログインは実行の冒頭に、サイトごとに 1 回だけ行えばよいこと
  （検証項目ごとに再ログインを求められないこと）
- 検証の途中で利用者に追加のログインを要求しないこと
- **楽天証券の12ページと TradingView への遷移は自動で行うこと。**
  利用者がこれらを手で開いて回らずに済むこと
- 以下は例外とし、**利用者が実行前にタブを開いておく**。
  ツールはそのタブを探して判定する

  | 対象 | 利用者がタブを開く理由 |
  | --- | --- |
  | SBI証券・個別銘柄 / ポートフォリオ | ページの URL がセッションと遷移経路に依存し、URL の指定だけでは開けない |
  | 楽天スーパースクリーナー | 結果一覧を出すには検索の実行（フォーム送信）が要る。CON-10 で禁止している |
  | SBI銘柄スクリーニング | 同上 |

  > いずれもログインのついでに開けるため、利用者の手間はログイン操作から実質増えない。
  > タブが無い場合は「破損」ではなく「未実施」として記録する（FR-17）
- ログイン待ちに時間制限を設けないこと（所要時間は利用者次第）
- あるサイトの検証が失敗しても、残りのサイトの検証が続行され、
  最後まで実行された結果が出力されること

**流れ:**

1. 開発者が検証を開始する（`npm run check:selectors` を想定。名称は設計で変わってよい）
2. ブラウザが開く
3. 開発者が対象サイトにログインし、**上記の例外4対象のタブを開いておく**
   （サイトごとに 1 回。時間制限なし）
4. 開発者が合図を出す
5. ツールが自動で開ける対象ページへ順に遷移し、
   例外4対象は開かれているタブを探して、セレクタのヒット有無を自動で判定する
6. 結果が出力される（FR-17）
7. ブラウザのプロファイルが破棄される（NFR-12）

**人が行うこと / ツールが行うこと:**

| 行為 | 担当 |
| --- | --- |
| ログイン | **人**（ツールは代行しない。CON-04, CON-10） |
| 楽天証券12ページ・TradingView への遷移 | ツール |
| SBI証券2ページ・スクリーナー2種のタブを開く | **人**（上記の例外） |
| TradingView の銘柄切り替え | ツール |
| TradingView チャート上での右クリック（メニューを開く） | ツール |
| メニュー項目の選択・遷移 | **行わない** |

| | |
| --- | --- |
| 優先度 | 重要 |
| 状態 | ⚠️ `npm run check:selectors` で1回の実行で通せる。ただし上記4対象は利用者がタブを開いておく必要がある（SPEC-SC-18 に限界として記載） |

## FR-18 TradingView の右クリックメニューを1項目に集約する ✅

TradingView のチャートの右クリックメニューに拡張が追加する行を1行にまとめ、
遷移先サイトはその入れ子（サブメニュー）に出すこと。

**困りごと:** 現在は有効な遷移先サイトが平らに並ぶため、20件有効なら20行伸びる。
メニューが長くなり、目的のサイトを探しにくい。

**判定基準:**

1. チャートを右クリックしたとき、拡張が**メニュー直下に追加する行は常に1行**であること
   （区切り線を除く）。有効サイトの件数、および楽天証券・内藤証券の項目の有無に関わらず、
   直下の行数は変わらない
2. その1行のラベルが「`<銘柄コード>` を開く」であること
   （国内株は「`7203` を開く」、米国株は「`AAPL` を開く」）。**銘柄名は出さない**
   （TradingView のメニューに既に出ているため）
3. その行にホバーすると、有効な遷移先サイトの一覧が入れ子で開くこと
4. 入れ子の中身が次の順に並ぶこと

   | 順 | 内容 |
   | --- | --- |
   | 1 | 楽天証券・内藤証券の項目（FR-06。ログイン中のみ出る） |
   | 2 | 区切り線（上が1件以上あるときのみ） |
   | 3 | 情報サイトの項目。**オプションページで設定した並び順（FR-09）と一致すること** |

5. 入れ子の項目をクリックすると、その銘柄のページが新しいタブで開くこと（現行と同じ）
6. **有効な遷移先サイトが0件のときは、直下の1行ごと出さないこと**（現行と同じ）
7. 入れ子が画面に収まらない長さになった場合、**入れ子の中をスクロールして
   すべての項目に到達できる**こと。
   スクロールせずに全項目が見えることは求めない
8. 入れ子が開いた状態で **Esc キー**を押すと、メニューが閉じること
9. 入れ子が開いた状態で**メニューの外をクリック**すると、メニューが閉じること
10. 追加した1行と入れ子の見た目が、TradingView 自身のサブメニュー
    （「チャートテンプレート ▶」など）と揃っていること（判定は目視）

**やらないこと:**

- ツールバーの「株Link」ボタンのメニュー（SPEC-CS-12）は**今回のスコープ外**。
  同じ「長い」問題を抱えるが、独立したメニューなので別要件として扱う
- 楽天証券・SBI証券のページのメニューは対象外
- 入れ子内での検索・絞り込みは作らない
- **キーボードでの項目移動・決定（矢印キー・Enter）は対象外。**
  キーボード操作は Esc による閉じのみを対象とする

**制約との関係（CON-03）:**

TradingView のサブメニューの開閉はサイト側の JS が担っており、拡張から呼べない。
開閉は拡張が自前で持つ。見た目を合わせる模倣用クラス（SPEC-CS-16）が
TradingView 側の改修で変わると見た目は崩れるが、**崩れても項目の選択と遷移は動くこと**。

| | |
| --- | --- |
| 優先度 | 重要 |
| 状態 | ✅ 実装済み（1.11.0）。判定基準 1〜10 を未ログイン環境・ログイン環境（楽天証券）の両方で確認（2026-08-23、`docs/MANUAL-CHECKLIST.md` A-10 / A-11 に記録）。既知の制限: 左反転時に親メニューと 5px 重なる（SPEC-CS-17） |
| 仕様 | SPEC-CS-11, SPEC-CS-16, SPEC-CS-17, SPEC-CS-18 |
| 既知の制限 | 左側に反転したとき入れ子が親メニューに約 5px 重なることがある（SPEC-CS-17）。項目はすべてクリックでき、判定基準5・7 は満たす |
| 関連 | FR-04, FR-06, FR-07, FR-09, CON-03, CON-08 |
| 確定 | 2026-08-23 に利用者と合意（ラベル文言・入れ子の並び・0件時・スクロール・キーボード範囲） |

### FR-19 TradingView のウォッチリストの行から遷移先サイトを開ける ❌

TradingView のウォッチリストで銘柄行を右クリックしたとき、
**その行の銘柄**について遷移先サイトを開けること。

**困りごと:** 現在はウォッチリストで見つけた銘柄を調べるのに、
いったんチャートの銘柄を切り替えてから右クリックする必要がある。

**判定基準:**

1. ウォッチリストの銘柄行を右クリックすると、拡張の項目が出ること
2. 出る項目の銘柄が、**右クリックしたその行の銘柄**であること。表示中チャートの銘柄ではない
   （チャートに銘柄 A を表示した状態でウォッチリストの銘柄 B を右クリックしたら、B のリンクが出る）
3. 行から銘柄コードが読み取れないときは、項目を追加しないこと（誤った銘柄のリンクを出さない）
4. メニューの形は FR-18 に従う（直下1行＋入れ子）
5. チャートとウォッチリスト以外（ツールバー・銘柄検索など）では、
   引き続き項目を追加しないこと（FR-04）

**FR-04 との関係:**

FR-04 は「チャート領域上で右クリックしたときに限る」と定めている。
これは「ウォッチリストで銘柄 B を右クリックしたのに、表示中チャートの銘柄 A のリンクが出る」
退行を防ぐためのもの。本要件はこの禁止を全面的に解くのではなく、
**右クリックした行から銘柄を特定できる場合に限って**対象を広げる。
判定基準 2 を満たさない実装は FR-04 違反として扱う。

取れないと判明した場合はこの要件を取り下げる。
