# 機能要件

## FR-01 Chrome 拡張機能として動作する

Chrome にインストールでき、Chrome ウェブストアで配布できる形式であること。

| | |
|---|---|
| 優先度 | 必須 |
| 状態 | ✅ |
| 仕様 | SPEC-MF-01 |

---

## FR-02 楽天証券のページで銘柄コードからリンクメニューを開ける

楽天証券の以下のページで、表示されている銘柄コードにホバーすると
遷移先サイトの一覧が出て、選ぶと新しいタブでその銘柄のページが開くこと。

- お気に入り / お気に入り編集
- 保有商品一覧（すべて / 国内株式）
- ランキング（売買代金 / 出来高 / 値上り値下り / 信用残 / 積立 / 楽天内）
- 国内株式（個別銘柄 / 株価検索）
- スーパースクリーナー

| | |
|---|---|
| 優先度 | 必須 |
| 状態 | ✅ |
| 仕様 | SPEC-CS-01〜08, SPEC-MF-06 |

---

## FR-03 SBI証券のページで銘柄コードからリンクメニューを開ける

SBI証券の以下のページで FR-02 と同じことができること。

- 国内株式・個別銘柄
- ポートフォリオ
- 銘柄スクリーニング

| | |
|---|---|
| 優先度 | 必須 |

| 仕様 | SPEC-CS-09, SPEC-CS-10, SPEC-MF-06 |

## FR-04 TradingView から遷移先サイトを開ける

TradingView のチャート画面で、表示中の銘柄について遷移先サイトを開けること。

- チャートの右クリックメニューに項目を追加する
- ツールバーに専用ボタンを置き、そこからも開ける
- 銘柄コードが取得できないときはボタンを出さない

| | |
|---|---|
| 優先度 | 必須 |
| 状態 | ✅ |
| 仕様 | SPEC-CS-11, SPEC-CS-12, SPEC-TC-07 |

---

## FR-05 選択した文字列から遷移先サイトを開ける

任意のページで文字列を選択して右クリックすると、遷移先サイトの一覧が出ること。
選択文字列の先頭が銘柄コードと解釈できる場合のみページを開く。

| | |
|---|---|
| 優先度 | 必須 |
| 状態 | ✅ |
| 仕様 | SPEC-SW-02, SPEC-SW-05, SPEC-TC-08 |

---

## FR-06 ログイン中の証券会社サイトの該当銘柄ページを開ける

利用者が既に証券会社にログインしているとき、TradingView から
その証券会社の該当銘柄ページを直接開けること。

- 対象: 楽天証券（国内株・米国株）、内藤証券（国内株のみ）
- **ログインしていない場合はメニューに出さない**（エラーを出さない）
- 拡張機能がログイン操作を代行することはない

| | |
|---|---|
| 優先度 | 重要 |
| 状態 | ✅ |
| 仕様 | SPEC-SW-06, SPEC-SW-07, SPEC-MSG-02, SPEC-MF-03 |

---

## FR-07 遷移先サイトを定義で管理できる

遷移先サイトは1箇所の定義で管理し、追加・削除がそこだけで完結すること。

- 銘柄コードを URL に埋め込めること
- 国内株と米国株で異なる URL 形式に対応できること
- 米国株に対応しないサイトは米国株のメニューに出さないこと

| | |
|---|---|
| 優先度 | 必須 |
| 状態 | ✅ |
| 仕様 | SPEC-EL-01, SPEC-EL-03, SPEC-EL-06, SPEC-TC-05 |

---

## FR-08 国内株と米国株の銘柄コードを判別できる

文字列から銘柄コードを取り出し、国内株か米国株かを判別できること。

- 国内株: 4桁。**2024年以降の英字を含むコード（例 `135A`）に対応すること**
- 米国株: 英字1〜5文字。取引所コード（`NASDAQ` / `NYSE`）が付く場合も扱えること
- **日本語文中の大文字並びを誤って米国株と判定しないこと**

| | |
|---|---|
| 優先度 | 必須 |
| 状態 | ✅ |
| 仕様 | SPEC-TC-01〜04 |

---

## FR-09 遷移先サイトを利用者が選択・並び替えできる

オプションページで以下ができること。

- 遷移先サイトごとに利用する/しないを切り替えられる
- ドラッグで表示順を変えられる
- 設定は保存され、次回以降も維持される
- 各サイトのトップページを開けるリンクがある
- 初期状態では全サイトが有効

> 既定で全部有効にしているためメニューが長い。利用者が絞り込む前提の設計。

| | |
|---|---|
| 優先度 | 必須 |
| 状態 | ✅ |
| 仕様 | SPEC-OP-03〜09, SPEC-ST-01, SPEC-ST-02 |

## 未達・検討中

### FR-12 セレクタ破損の検知 ❌

注入対象サイトの改修でセレクタが効かなくなったことを、利用者からの報告以外で検知できること。

| | |
|---|---|
| 優先度 | 希望 |
| 状態 | ❌ 未達。現状は報告があってから調査している |
| 備考 | 自動テストはフィクスチャに対するもので、実サイトの変更は検出できない |

### FR-13 注入失敗時のリトライ ❌

固定待機時間内にサイト側の描画が終わらなかった場合でも、最終的にメニューが注入されること。

| | |
|---|---|
| 優先度 | 希望 |
| 状態 | ❌ 未達。固定待機（500ms / 1500ms）のみでリトライしない（SPEC-CS-01） |

### FR-14 取引所コード付きシンボル表記を正しく解釈する ❌

`EXCHANGE:TICKER` 形式（例: `NYSE:AAPL`、`TSE:7203`）から銘柄コードを正しく取り出せること。

TradingView のシンボル表記がこの形式のため、コピーして右クリックする使い方と直撃する。

| | |
|---|---|
| 優先度 | 重要 |
| 状態 | ❌ 未達。現在は `NYSE:AAPL` から `NYSE` を銘柄コードとして取り出してしまう（SPEC-TC-03 の「既知の弱点」） |
| 備考 | 取引所コードの一覧（`NASDAQ` / `NYSE` / `TSE` / `TSE_DLY` / `BATS` 等）を定義し、`EXCHANGE:` 接頭辞として先に剥がす設計が必要 |
