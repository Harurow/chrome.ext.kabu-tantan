| | |

## 0. 何が壊れていたか（前提の事実）

| 対象 | 旧 | 現行 DOM（2026-08-23 実測 / 未ログイン / `TSE:7203`） |
| --- | --- | --- |
| ツールバー挿入先 | `div.container-hw_3o_pb` → 0件 | `div.container-OH8c8Nc3` → 1件 |
| 右クリックメニュー | `div.menu-Tx5xMZww.context-menu.menuWrap-Kq3ruQo8 > div > div[data-name="menu-inner"] > table` → 0件 | `div.context-menu table` → 1件。`data-name="menu-inner"` は消滅 |
| メニュー1行目 | 銘柄コードで始まる前提 | 「チャート表示をリセット」。銘柄は8行目以降にしか出ない |
| 模倣用クラス | `-GJX1EXhk` / `-DFIg7eOh` / `-rm8yeqY4` 等 | ハッシュが総入れ替え。`wrapper-NLkHhUu3` は後継なし |

**セレクタを直すだけでは右クリックメニューは動かなかった。** 銘柄コードの取得方式が前提ごと壊れていた。

## 1. 右クリックメニューの銘柄コードをどこから取るか

**決定: チャート canvas の `aria-label`（`getTickerCode()`）に一本化する。**

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **(a) 採用** | `getTickerCode()`（SPEC-TC-07）を呼ぶ。メニューのテキストを読まない | メニュー構成の変更から独立する。ボタン側と取得元が揃い、経路が1本になる |
| (b) | メニューの**全行**を走査して銘柄コードらしい文字列を探す | 却下。「価格 3,060 で 7203 にアラートを追加」のような文から拾うことになり、価格・数量を銘柄と誤認する余地が残る。文言は TradingView の翻訳変更でも変わる |
| (c) | 1行目固定をやめ、`n` 行目固定にする | 却下。(b) 以上に脆い。メニュー項目は権限・銘柄種別で増減する |

**退行の有無を実測で確認した。** 旧方式は「1行目が `[A-Z]{1,5}` で始まれば米国株」で
取引所を問わなかったのに対し、canvas 経路は取引所接頭辞に依存する。
しかし**未ログインの TradingView は米国株の提供元を BATS に置き換える**ため
（`NASDAQ:AAPL` を指定しても `aria-label` は `BATS:AAPL …`）、未ログインでは退行しない。
ログイン済みの表記は未確認のため、2 で接頭辞を広げて塞いだ。

代償: **右クリックした場所ではなく、チャートが表示している銘柄**のリンクになる。
ウォッチリスト等を右クリックした場合に別銘柄のリンクを出しうる。これは 3 で塞いだ。

## 2. 取引所接頭辞をどこまで広げるか（FR-14 との切り分け）

**決定: 取引所コードの表 `exchanges` を `src/urls.js` に置き、
TradingView 側の `getTickerCode()` だけが参照する。Service Worker 側（FR-14）は今回やらない。**

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **(a) 採用** | `exchanges` を `urls.js` に置く。TradingView の canvas 解釈のみ差し替える | FR-04 の修正に必要な最小。表の置き場所だけ先に正しくしておけば FR-14 が二重定義にならない |
| (b) | FR-14 ごと今回やる（選択文字列の `NYSE:AAPL` 解釈も直す） | 却下。SPEC-TC-02〜04 は NFR-04（誤爆させない）と直結し、自動テスト8件が乗っている領域。DOM 破損の緊急修正と混ぜると、どちらの回帰か切り分けられなくなる |
| (c) | 表を `tradingview-cs.js` のローカル定数にする | 却下。FR-14 に着手した時点で Service Worker 側に同じ表が生まれる。`urls.js` は Service Worker も Content Script も既に読んでいるので、置くコストはゼロ |
| (d) | `BATS:` 限定のまま（表を作らない） | 却下。ログイン済みで `NASDAQ:` 表記になる場合に右クリック・ボタンとも動かない。旧方式にあった「取引所を問わない」性質を失ったままになる |

`_DLY` は接尾辞として剥がす規則にした。`TSE_DLY` / `NASDAQ_DLY` / `BATS_DLY` を個別に列挙すると
表が倍になり、列挙漏れが機能停止に直結するため。

## 3. 右クリック以外で開くメニューに項目を出さない方法

**決定: `document` の `contextmenu`（キャプチャ）を監視し、
発生元が `div.chart-gui-wrapper` の内側だったときから 1500ms 以内に限って拡張する。**

旧実装は「1行目が銘柄コードか」の判定が**結果的なフィルタ**になっていた。1 でこれを捨てるので、
代わりの絞り込みが要る。`div.context-menu` は TradingView が右クリック以外のメニューにも使いうる。

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **(a) 採用** | `contextmenu` イベントの発生元と時刻で絞る | 起点が意味的に正しい。過剰に発火しない。`check:selectors` の右クリック操作（SPEC-SC-11 手順4）でも成立するので、注入件数で確認できる |
| (b) | 絞らない（`div.context-menu` なら全部拡張する） | 却下。ツールバーのドロップダウン等に「7203 を株探で開く」が混ざる可能性がある。他社サイトの DOM を余計に書き換えない（CON-03） |
| (c) | メニュー内に銘柄コードを含む行があるかで判定する | 却下。1 の (b) と同じ理由（文言依存）に逆戻りする |

`div.chart-gui-wrapper` は `chart-canvas` セレクタの一部と同じ、ハッシュを含まないクラス。
**`menuSelectors` には足さない。** 足すと SPEC-SC-02 の検証対象が5対象に増え、
`scripts/selector-check/targets.mjs` にページ識別セレクタの追加が要る（FR-12 の対象は
「壊れると機能が消えるもの」で、この判定が壊れたときの被害は過剰注入であり機能消失ではない）。

## 4. ツールバー挿入先のセレクタ

**決定: 実測値 `div.container-OH8c8Nc3` をそのまま使う。**

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **(a) 採用** | `div.container-OH8c8Nc3` | 実測で1件。ハッシュが変われば `check:selectors` が破損として検出する（FR-12 の想定どおりの壊れ方） |
| (b) | `div.chart-gui-wrapper__legend div[class^="container-"]` のような前方一致 | 却下。**未実測**。`container-` 接頭辞は TradingView 全体で多用されており、複数ヒットするとボタンが複数出る。壊れ方が「機械判定できる破損」から「見た目の異常」に変わるのは後退 |
| (c) | 買/売ボタンの並びを避け、`legend-quatTGAC` 直下に置く | 保留。ハッシュ依存の度合いは (a) と同じで、利点は「未ログインでも見える可能性がある」点のみ。**A-1 の目視でボタンが見えなかった場合の次の候補**として残す |

未ログインでは container の子に `blockHidden-wVrpb0RA` が付き、container の幅・高さが 0 になる。
**セレクタのヒット（存在）とボタンの可視性は別問題**である点を SPEC-CS-12 に明記し、
可視性の確認は手動 A-1（ログインして実施）に振り分けた。

## 5. `wrapper-NLkHhUu3` の後継が無い件

**決定: 要素ごと省略し、`<a>` を `span.label-…` の直下に置く。**

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **(a) 採用** | `<div>` を削除する | 現行 DOM に `wrapper-` の後継が無い＝TradingView 自身がこの階層をやめた。無い階層を模倣しても見た目は合わない |
| (b) | クラス無しの `<div>` を残す | 却下。何も指定しない `<div>` はレイアウト上の意味を持たず、残す理由が「元々あったから」以外に無い |
| (c) | 適当に近いハッシュ付きクラスを当てる | 却下。役割の異なるクラスを当てると、そのクラスの CSS が変わったときに崩れ方が読めなくなる |

`<a>` のインラインスタイル（`color: var(--tv-color-popup-element-text); width: 100%;`）は
そのまま維持する。崩れた場合は (b) を試す。判定は手動 A-10。

## 6. 模倣用クラスがまた変わったときの備え

**決定: 1つの定数 `tvMimicClasses` に集約する（SPEC-CS-16）。検証対象には格上げしない。**

| 案 | 内容 | 判定 |
| --- | --- | --- |
| **(a) 採用** | 模倣用クラスを1定数に集約し、採取日をコメントに残す。気づく手段は手動確認のまま | 次に変わったときの修正が1箇所で済む。`menuSelectors`（検出用）との区別が構造として表れる |
| (b) | 現状維持（HTML 文字列に直書き） | 却下。今回12種を4箇所から拾い出すのに実 DOM の確認が必要だった。次も同じ作業が発生する |
| (c) | `check:selectors` の検証対象に加える | 却下。FR-12 が「模倣用クラスは検証対象外」と明示している。判定を足すと「見た目が古いだけで機能は正常」を破損として報告することになり、**破損の意味が薄まる**（❌ が出ても直さなくてよい場合が生まれる） |

(a) だけでは「崩れたことに気づけない」という指摘はそのとおりで、**現行の A-9
（ダーク/ライトで文字が読めるか）では不足している。** A-9 は「株Link」ボタンしか見ていない。
右クリックで追加した項目・区切り線の見た目を見る **A-10 を新設した**。

模倣用クラスが古くなっても機能は落ちない。**気づくのが次のリリース確認になっても損害が
「見た目が TradingView と揃わない」に限られる**ことを、格上げしない根拠とする。
