## 書き方

- 1判断1ファイル。`NNNN-<英小文字ハイフン>.md`
- **選ばなかった案とその理由を必ず書く。** 採用案だけ書くと後で再検討できない
- 決まった内容そのものは `docs/specs/` に書く。ADR には「なぜそれにしたか」だけを書く
- 覆した場合はファイルを消さず、状態を「置き換え（→ NNNN）」に変える
- **1つの ADR が当初の題を超えて育つことがある。** 0009 がその例で、`EXCHANGE:TICKER` の解釈から
  始まり、レビューの連鎖で**銘柄コードの切り出し規則そのもの**（FR-08）の作り直しに至った。
  表題は変えずに、上表の説明と本文の追補で範囲の広がりを示す

> **件数を本ファイルに書かない。** 自動テストの件数は `docs/TEST-CATALOG.md`（生成物）が正本で、
> `npm run docs:tests:check` が実物と機械的に突き合わせる**唯一の場所**。
> 人が読む要約は `docs/TESTING.md`。**索引に数を写すと実装が進むたびに取り残される**
> （実際に3度指摘された。SPEC-SC-16 の同趣旨の注記）。
>
