# ADR-0014 証券会社サイトの一覧で米国株の行にもメニューを出す方法

| | |
| --- | --- |
| 状態 | 採択（2026-08-30）。**未実装**（1.17.0 予定） |
| 対象 | FR-28（＋ FR-02, FR-03, FR-05, FR-07, FR-08, FR-13, FR-19, NFR-01, NFR-13, CON-02, CON-03） |
| 仕様 | [SPEC-CS-26](../specs/content-scripts.md), [SPEC-CS-06](../specs/content-scripts.md), [SPEC-TC-10](../specs/ticker-code.md), [SPEC-TC-02](../specs/ticker-code.md) |
| 発端 | 利用者の報告「お気に入り、保有商品一覧で米国株がメニューでない」（2026-08-30）。**破損ではなく未実装**で、原因は3箇所（抽出・セレクタ・URL 選択） |

---

## 0. 何が起きているか

注入経路（楽天2本・SBI2本）は初版から**国内株4桁専用**である。

| 箇所 | 現状 | 結果 |
| --- | --- | --- |
| 抽出 | 4本とも `/[0-9][0-9ACDF…][0-9][0-9ACDF…]/g` を直書き | ティッカーはどのページでも取れない |
| セレクタ | 楽天・保有商品一覧（すべて）が `td:contains("国内株式") + td` | 米国株の行は走査対象にすらならない |
| URL 選択 | `linkMenu.js` の `createMenu` が `url1` 固定 | 仮に取れても国内株用 URL にティッカーを当てはめる |

右クリック（FR-05）と TradingView（FR-04 / FR-19）は米国株で動く。**注入経路だけが取り残されている。**

---

## 1. 米国株の抽出を「どこで」有効にするか

**決定: `menuSelectors` の各エントリに `us: true` を書いたときだけ有効にする（opt-in）。**

| 案 | 内容 | 判定 |
| --- | --- | --- |
| A | **エントリごとの opt-in（`us: true`）** | **採用** |
| B | 全エントリで一律に有効 | 不採用 |
| C | 対象外エントリに `us: false` を書く（opt-out） | 不採用 |

**理由。** 米国株の抽出は「先頭が大文字英字 1〜5 文字＋許可された後続」に当たれば成立する。
これを全エントリに効かせると、ランキングの `td.align-C` や個別銘柄の `h1` など
**FR-28 が対象外と決めたページ**（適用範囲 d〜g）でも成立しうる。
成立してしまった場合の失敗は「**別銘柄のページが静かに開く**」で、ADR-0009 が最悪と決めた失敗と同じ型。

**許可列挙（opt-in）と禁止列挙（opt-out）の代償の差**は FR-23 / FR-08 で繰り返し出た形と同じ。

| 方式 | 外したときの失敗 | 気づけるか |
| --- | --- | --- |
| opt-in | 米国株でメニューが出ない（＝今日と同じ状態） | 利用者が気づく（現に気づいて報告された） |
| opt-out | 想定外のセルにメニューが出て別銘柄が開く | **気づけない**（黙って間違える） |

**代償。** FR-28 は「スクリーナー系にも自動的に効く」と書いている（適用範囲 f の但し書き）が、
opt-in ではスクリーナーに米国株の行が並ぶことが判明したとき **`us: true` を1行足す**必要がある。
**新しい調査も新しいロジックも要らない**（データの1行）ので、但し書きの趣旨
（見立てが外れても手戻りが出ない）は保つ。

## 2. 国内株と米国株のどちらを先に判定するか

**決定: 国内株（現行の非アンカー4桁）を先に試し、空振りしたときだけ米国株を試す。**

| 案 | 内容 | 判定 |
| --- | --- | --- |
| A | **jp → us の順（jp は現行の式のまま）** | **採用** |
| B | us（アンカーあり）→ jp の順 | 不採用 |
| C | 行の種別（商品種別の列・取引所の列）で先に決める | 不採用 |

**A の決め手は「国内株の結果が1文字も変わらない」ことを構造で保証できる点。**
FR-28 判定基準 5（国内株の退行を出さない）は、この設計では**論理的に破れない**。
米国株の抽出が走るのは、**今日の実装が何もしていない要素**だけである。

> **この保証は「抽出」の話に限る。** 同じバッチで入れる 5（0件なら `null`）と
> 7（テキストノード1件で打ち切り）は**国内株側の見え方も変える**。
> 判定基準 5 が見ているのは「集合・順序・リンク先」なので違反ではないが、
> **「抽出が変わらない＝国内株が何も変わらない」ではない。**

**B を採らない理由。** `TSE 7203` のような「英字＋国内コード」のセルがあると、
米国株として `TSE` を切り出し、**今日は正しく動いている国内株の行を壊す**。
実 DOM を確かめずに国内株側を危険に晒す変更はしない（CON-03）。

**C を採らない理由。** 判定基準 9 が「行から取引所が読み取れなくても成立すること」を求めている。
種別の列に依存すると、列が無いページ（お気に入り）で成立しない。
種別の列は**走査対象を絞る**ためだけに使う（下記 4）。

**A の残る危険（記録）。** 米国株のセルに4桁の数字が並ぶと（例 `AAPL 1234.5`）、
国内株として `1234` を切り出す。**対象セルはコード列**であり実例は確認していないが、
**確認手順（C-1 / C-3 の米国株の手順）で「開いたページが米国株のものか」を必ず見る**。
実例が出たら、そのページのセレクタを絞る（セレクタ側で直し、抽出規則は動かさない）。

## 3. 米国ティッカーの書式（後続境界）を注入経路にどう持ち込むか

**決定: `usCodePattern` を `src/service_worker.js` から `src/urls.js` へ移し、共有する。**

| 案 | 内容 | リテラル数 | 判定 |
| --- | --- | --- | --- |
| A | **`usCodePattern` を `urls.js` へ移して Service Worker と注入経路で共有** | 3 | **採用** |
| B | `linkMenu.js` に4本目のリテラルを書く | 4 | 不採用 |
| C | TradingView 側（`parseExchangeSymbol`）も `urls.js` へ寄せて一本化 | 2 | 不採用 |

**A の理由。** `urls.js` は Service Worker（`importScripts`）・注入経路4本・TradingView・
オプションページの**すべてが読み込む唯一のファイル**で、`exchanges` を既にそこで共有している。
移動は**式を1文字も変えない純粋な移設**で、手で保つ複製を増やさずに済む（NFR-13）。

**B を採らない理由。** 境界の複製が4本になる。テストで同一性は保てるが、
**同一性を機械で保つのは「共有できないとき」の次善策**（ADR-0009 の 3）。
ここは共有できる（同じスクリプトが両方に読み込まれる）ので、次善策を選ぶ理由が無い。

**C を採らない理由。** ADR-0009 の 3 の判断（入力の性質・失敗時の扱い・戻り値の形が違うので
解析器は共有しない）を今回覆す材料は無い。TradingView 側は据え置く。

### 4経路目・5経路目の扱い（テストの改訂）

`米国ティッカーの後続境界: 3経路で同じ値`（`tests/service-worker.spec.mjs`）は
**2ファイルから `[A-Z]{1,5}` を含む正規表現リテラルを集めて3件**であることを固定している。

| | 現行 | 本 ADR 適用後 |
| --- | --- | --- |
| 読むファイル | `service_worker.js`, `tradingview-cs.js` | **`urls.js`**, `service_worker.js`, `tradingview-cs.js` |
| リテラル数 | 3 | **3（変わらない）** |
| 抽出の経路 | 3（選択文字列2 ＋ TradingView） | **5**（選択文字列2 ＋ TradingView ＋ 注入経路 ＋ ウォッチリスト） |

**リテラル数が変わらないのは、注入経路が新しいリテラルを作らずに `usCodePattern` を使うから。**
テスト名の「3経路」は**リテラル3本**の意味に読み替える（改称する。SPEC-TC-02）。
**読むファイルに `urls.js` を足さないと、移設した瞬間に件数が 3→2 に落ちてテストが落ちる**
（＝移設を検知する。落ちたら期待を直すのではなく、読む対象を足す）。

## 4. 保有商品一覧（すべて）で米国株の行にどう届かせるか

**決定: 既存エントリのセレクタに `td:contains("米国株式") + td` をカンマで足す。**

| 案 | 内容 | 判定 |
| --- | --- | --- |
| A | **同一エントリにカンマで足す（許可するラベルは「米国株式」だけ）** | **採用** |
| B | 「外国株式」「海外株式」も足す | 不採用 |
| C | `td:contains("株式") + td` にまとめる | 不採用 |
| D | 米国株用に**別エントリ**を新設する | 不採用 |

**B・C を採らない理由（同じ）。** 上位ラベル（外国株式・株式）は**中国株式・アセアン株式を含みうる**。
そこに届くと、`00700` のような数字コードに**国内株の非アンカー抽出が当たり `0070` を切り出す**
（判定基準 6 違反・別銘柄が開く）。**米国株式に絞れば、外れても 0 件で今日と同じ**である。

**D を採らない理由。** `scripts/selector-check/targets.mjs` と `menuSelectors` は
`key ?? title` で**1対1**に対応させてある（SPEC-SC-05）。エントリを増やすと
検証ツール側（別担当が FR-23 で作業中）に追随が要る。**カンマなら 12 件のまま変わらない**
（`ランキング・楽天内` に先例がある）。

**A の代償（記録）。** カンマを含むセレクタは `check:selectors` の「手がかり」で
**段階ごとの件数に分解されない**（`カンマを含むセレクタは分割しない`）。
保有商品一覧（すべて）は現在 ⚠️ 未到達で、到達できたときの診断がその分だけ粗くなる。
**到達性（FR-23）の課題とは別軸**なので、FR-23 の結論を待たずに進める。

**ラベルの実測が残る。** 「米国株式」は実 DOM で確認していない。外れた場合は
**0 件＝今日と同じ挙動**に倒れるので害は無い。C-1 の追加手順で**実際のラベルを記録**し、
違っていたらその1語を直す。

## 5. 遷移先が0件のときメニューを出さない

**決定: `createMenu` は項目が0件なら `null` を返し、呼び出し側は置換しない。**

TradingView 側は既にそうなっている（`hasBroker` も `linkItems` も無ければ何も作らない）。
FR-28 判定基準 4 はこれに揃えたもの。**国内株にも同じ規則を効かせる。**

- 今日は、遷移先を全部無効にすると**空の箱**がホバーで開く（利用者から見れば故障）
- 国内株で「集合・順序・リンク先が変わらない」（判定基準 5）は、
  **有効な遷移先が1件でもある限り**成立する。0 件のときだけ差が出て、それは改善方向

## 6. 米国株では `url2` を使わない

**決定: 注入経路は常に `url3`（取引所コード無し）を使う。**

判定基準 9 が「行から取引所が読み取れなくても成立すること」を求めており、
証券会社の一覧に取引所の表示があるとは限らない。**取引所を推測しない。**

**右クリックと同じ結果になる。** 同じセルの文字列（例 `AAPL`）を選択して右クリックすると、
`getTickerCode` は `exchange` を返さず、`getUrl` は `url2` の条件（`exchange` あり）を外れて
`url3` を使う（SPEC-TC-05）。**注入メニューと右クリックの URL は文字列として一致する**
（判定基準 2・3）。

**並ぶ集合は `url3` を持つサイト**（現在6件）で、順序はオプションの並び順のまま。

> **判定基準 3 の読み方。** 「並ぶ集合と順序が右クリックと一致すること」を
> **Chrome のコンテキストメニューに見えている項目**と読むと成立しない。
> あちらは有効な全キーから静的に作られ、米国株非対応サイトも**項目としては出る**（SPEC-TC-05）。
> **本 ADR は「その銘柄のページが開く遷移先の集合と順序」と読む。**
> 判定基準 3 の第1文（米国株のページを持たない遷移先は並ばない）と FR-07 に一致する読み。
> **analyst に文言の確認を残す**（設計は第1文に従うので、どちらに転んでも実装は変わらない）。

## 7. 1行につきメニューは1つ

**決定: 銘柄コードを含むテキストノードのうち、最初の1件だけを置換する（`break`）。**

現行は要素内の**すべての**該当テキストノードを置換する。同じコードが2回現れるセルでは
メニューが2つ出る（判定基準 10 違反）。実例は確認していないが、
**規則としては1つに決める**方が判定基準に対して明確で、国内株でも害が無い。

> **これは国内株の挙動も変える。** 該当するセルがあれば、**国内株でも2つ目のメニューが消える**。
> 判定基準 5 は「集合・順序・リンク先」を見ており、そこは変わらないので違反ではない。
> **実装後に「国内株が退行した」と読まれないよう、ここに残す**
> （同じ理由で 5 の 0 件時の `null` も国内株に効く）。

## 8. 何を自動テストで固定し、何を人が見るか

CON-08（自動テストにできない）は **TradingView だけ**の制約で、楽天・SBI はフィクスチャで検証済み。
**判定基準 1〜8・10 はフィクスチャで固定できる。**

| 判定基準 | 固定の仕方 |
| --- | --- |
| 1 / 2 / 3 / 5 / 7 / 8 / 10 | `tests/content-script.spec.mjs`（米国株の行を含むフィクスチャ） |
| 4 | 同上（米国株非対応サイトだけを有効にした状態） |
| 6 | 同上（国内株の行と米国株の行を同じページに混ぜる） |
| 9 | 取引所の列を持たないフィクスチャで 1〜3 が成立すること |

**人が見るのは3つだけ。**

1. 実ページで米国株の行にメニューが出るか（C-1 / C-3 の追加手順）
2. **保有商品一覧（すべて）の商品種別ラベルの実測値**（上記 4）
3. SBI ポートフォリオに外国株式の行が並ぶか（FR-28 適用範囲 c。**並ばなくても未達としない**）
