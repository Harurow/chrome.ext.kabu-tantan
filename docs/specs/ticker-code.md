# SPEC-TC: 銘柄コードの判定規則

実装: `src/service_worker.js`（`getTickerCode`）、`src/*-cs.js`、`src/tradingview-cs.js`

> 節の並びは ID 順ではない。**SPEC-TC-09 は SPEC-TC-03 の直後**に置く（両者と SPEC-TC-04 の
> 優先順位を続けて読めるようにするため）。**SPEC-TC-10 は SPEC-TC-06 の直後**に置く
> （どちらも注入経路の抽出）。ID は採番順で、既存 ID は再利用しない。

## SPEC-TC-01 国内銘柄コードの形式

```text
[0-9][0-9ACDFGHJKLMNPRSTUWXY][0-9][0-9ACDFGHJKLMNPRSTUWXY]
```

4桁。2桁目と4桁目に英字が入りうる（東証が2024年から採番している英字含みコード、例 `135A`）。
使われる英字は上記21文字に限定される（`B` `E` `I` `O` `Q` `V` `Z` は数字との誤読防止で不使用）。

- 要件: FR-08
- 検証: `auto`（`getTickerCode › 4桁の国内銘柄コードを jp として認識する` / `英字を含む国内銘柄コード（例: 135A）も認識する`）

## SPEC-TC-02 米国銘柄コードの形式

> 後続境界を**許可列挙**にしたのは 1.15.0。要件は FR-08「切り出してよい後続だけを許す」、
> 判断は [ADR-0009](../adr/0009-exchange-prefixed-symbol.md) の 9・10。
> それ以前の**禁止列挙**（害のある記号を並べる形）の経緯は本節末尾の「経緯」。
>

```text
^\s*([A-Z]{1,5})<後続境界>\s*
```

大文字英字 1〜5 文字。**先頭アンカー `^` と後続境界の両方が必須。**

| 欠けるもの | 起きること |
| --- | --- |
| 先頭アンカー `^` | 日本語文中の大文字並びに誤マッチする（例:「株価はNYSEで上昇」→ `NYSE`） |
| 後続境界 | 別の表記に続いているものの手前を切り出す（例: `BRK.B` → `BRK`、`S&P500` / `S＆P500` → `S`、`SP500` → `SP`、`A－Z` → `A`）。**`A`（Agilent）・`S`（SentinelOne）・`SP` はいずれも実在するティッカー**で、**別銘柄のページを開くため、開かないより悪い** |

### 後続境界（許可列挙。FR-08）

**切り出してよいのは、直後の文字が次の4分類のいずれかに当たるときだけ。**
当たらない文字（未知の記号・数字・全角の連結記号を含む）が続く場合は何も返さない。

| # | 分類 | 中身 | 例 |
| --- | --- | --- | --- |
| 1 | 文字列の終わり | `$` | `AAPL` |
| 2 | 空白 | `\s`（半角・全角・改行・タブ） | `AAPL Apple Inc.` / `AAPL　MSFT` |
| 3 | **本文文字** | **非 ASCII の `\p{L}`**（かな・漢字・カタカナ・ハングル等）。**全角ラテン文字と長音符2字（`ー` `ｰ`）は除く** | `AAPLの株価` / `AAPL株` |
| 4 | **終止記号**（下表を列挙） | 文・引用・括弧を閉じるもの。**半角と全角の両方** | `AAPL,` / `AAPL、` / `AAPL）` |

**分類 4 の終止記号（半角と全角を対で持つ）。**

| 役割 | 半角 | 全角・和文 |
| --- | --- | --- |
| 読点・句点 | `,` | `，` `、` `。` |
| セミコロン・コロン | `;` `:`（下記の注） | `；` `：` |
| 感嘆・疑問 | `!` `?` | `！` `？` |
| 引用符 | `"` `'` | `＂` `＇` `‘` `’` `“` `”` |
| 丸括弧 | `(` `)` | `（` `）` |
| 角括弧・波括弧 | `[` `]` `{` `}` | `［` `］` `｛` `｝` |
| 和文の括弧 | — | `「` `」` `『` `』` `【` `】` `〈` `〉` `《` `》` `〔` `〕` |

**開き括弧も許可する**（`AAPL(Apple Inc.` / `AAPL（アップル）`）。
括弧は銘柄コードを別の表記に続けないため、閉じ括弧と扱いを変える理由が無い。

> **分類 3 で「非 ASCII」ではなく「非 ASCII の文字（`\p{L}`）」に絞るのが要点。**
> 「非 ASCII なら安全」は誤った代理指標で、全角の連結記号（`＆` `．` `－` `／` `＋`）や
> 中黒 `・`・ダッシュ類はすべて非 ASCII でありながら**別の表記に続けている**（FR-08 の訂正記録）。
> `\p{L}` は**連結記号を含まない**ので、この穴が構造的に塞がる。
>
> **全角ラテン文字（`Ａ`〜`Ｚ` / `ａ`〜`ｚ`）は分類 3 から除く。** 半角の英字を許可しない以上、
> 全角だけ許可すると `AAPLＡ` が開いて半角と食い違う。FR-08 の「全角英数字の認識は広げない」とも揃う。

**分類 3 から除く文字と、その基準。**

| 除く文字 | 理由 |
| --- | --- |
| 全角ラテン文字（`Ａ`〜`Ｚ` / `ａ`〜`ｚ`） | 半角の英字と揃えるため（上記） |
| **長音符2字（`ー` U+30FC / `ｰ` U+FF70）** | Unicode 上は「文字」（Lm）だが、**日本語 IME でハイフンを打つと出る**ため、`BRKーB` のように**連結記号の代用として実際に打たれる**（FR-08 判定基準 5） |

> **例外にする基準は「文字かどうか」ではなく、「連結記号の代用として実際に打たれるかどうか」。**
> この基準があるので例外は無制限に増えない。**反復記号（`々` `ゝ` `〆`）は許可のまま**で、
> `AAPL々` は `us AAPL` を返す（実測）。これらは連結記号の代用として打たれないため。
>
> `ｰ`（U+FF70 半角長音）を落とすと `BRKｰB` が素通りする。**長音符は2字ある**
> （当初「1文字の変更で済む」と書いていたのは誤り。ADR-0009 の 11）。

**分類 4 の `:` `：` は、選択の先頭では到達しない。**
先頭が `[A-Z]+:` の形なら SPEC-TC-09 が先に走り、**登録の有無にかかわらず打ち切る**
（FR-08 判定基準 7）。`AAPL:` / `AAPL: 100ドル` は何も返さない。
**コロンの前に空白があっても同じ**（`AAPL : 100` / `AAPL   :   100` / `AAPL ： 決算`）。
SPEC-TC-09 の区切りが `(\s*[:：]\s*|\s+)` で**コロンの前の空白まで飲む**ため。
効くのは `NYSE:AAPL:` / `NYSE:AAPL：決算` のように**取引所プレフィックスの後ろに来る場合**だけで、
そこでは `us AAPL @NYSE` を返す（実測。外すとこの形が落ちるため、許可列挙に残している）。

> **全角コロン `：` も同じ扱い。** SPEC-TC-09 が `:` と `：` の**両方**を区切りとして扱うため、
> `A：Z` は先頭で打ち切られる（半角の `A:Z` と同じ）。
> 一時期ここが食い違い、`A：Z` だけが `us A`（Agilent）を開いていた（ADR-0009 の 12）。

### 半角・全角で結果が変わらないこと（判定基準 5）

**機械的に検算した。** ASCII の記号・数字 42 種について、
`A<記号>Z` と `A<全角の記号>Z` の結果を突き合わせる（architect が実コードで確認）。

**現行は 42 / 42。例外なし。**

> **一時期 41 / 42 になっていた。** 判定基準 7（`X:Y` の打ち切り）を入れた直後、
> 半角の `A:Z` だけが止まり、全角の `A：Z` は `us A`（Agilent）を開いていた。
> SPEC-TC-09 の区切りに `：` を含めて解消した（ADR-0009 の 12）。

| 半角 | 全角・字形違い | 結果 |
| --- | --- | --- |
| `S&P500` | `S＆P500` | どちらも開かない |
| `BRK.B` | `BRK．B` | どちらも開かない |
| `A-Z` | `A－Z` / `A–Z` / `A—Z` / `A−Z` / `A―Z` / `A‐Z` / `A〜Z` / `A～Z` | すべて開かない |
| `AAPL/MSFT` | `AAPL／MSFT` | どちらも開かない |
| `A+` | `A＋` | どちらも開かない |
| `A_B` | `A＿B` | どちらも開かない |
| （半角に相当なし） | `AAPL・MSFT` / `AAPL･MSFT`（中黒） | 開かない |
| `BRK-B` | `BRKーB` / `BRKｰB`（長音符2字） | どちらも開かない |
| `AAPL,` | `AAPL，` | どちらも `us AAPL` |
| `AAPL)` | `AAPL）` | どちらも `us AAPL` |
| `A:Z` | `A：Z`（コロン） | どちらも開かない（SPEC-TC-09 が区切りとして扱い、打ち切る） |

> **英字は「連結記号」ではないので、この検算の対象外。**
> `A` ＋ ASCII 英字 ＋ `Z` は文字列全体が1つのティッカー（`AAZ`）として成立するのに対し、
> `AＡZ` は成立しない。これは規則の食い違いではなく、**半角英字だけを銘柄コードとして扱う**という
> SPEC-TC-01 / 02 の前提そのもの（FR-08「全角英数字の認識は広げない」）。

### NFKC 正規化を使わない理由（実測）

入力を NFKC 正規化してから判定する案は**採らない**。判断は ADR-0009 の 10。

| 理由 | 実測 |
| --- | --- |
| **判定基準 5 を満たさない** | `＆` `．` `－` `／` `＋` は半角に畳まれるが、**中黒 `・`、ダッシュ類（`–` `—` `―` `−` `‐` `‑` `‒` `゠`）、波ダッシュ `〜` は畳まれず素通りする**（`AAPL・MSFT` → `us AAPL`） |
| **FR-08 の範囲外の挙動変化が起きる** | `ＡＡＰＬ` → `us AAPL`、`７２０３` → `jp 7203` と**全角英数字を認識するようになる**。FR-08 は「認識を広げない」と決めている（`Ａ社` → `A` という新しい偽陽性が生まれる） |
| 許可列挙なら不要 | 分類 3 を `\p{L}` にした時点で、全角の連結記号は**正規化なしで**落ちる |

### 許容した代償

| 落ちる入力 | 備考 |
| --- | --- |
| `AAPL.` / `AAPL. Apple` | `.` を許可すると `BRK.B` を止められない（FR-08「やらないこと」） |
| `AAPL-Apple` / `AAPL/MSFT` / `AAPL+` / `AAPL&` | 現行から変わらない |
| `AAPL#` / `AAPL=` / `AAPL*` / `AAPL$` / `AAPL%` / `AAPL@` / `AAPL_B` など | 列挙にない ASCII 記号。実例が見つかっていない |
| **`AAPL:` / `AAPL: 100ドル`** | FR-08 判定基準 7 の代償。コロンごと選択する必要があり経路が細い。`X:Y` を記号表記として扱う側を採った |
| **`AAPL：` / `AAPL：決算発表`（全角コロン）** | 半角の `AAPL:` と同型。判定基準 5 を例外なしにするために揃えた |
| **`AAPL : 232.50` / `AAPL : MSFT` / `AAPL ： 決算`（コロンの前に空白がある形）** | 引用・見出しの表記。**空白を挟んでも落ちる唯一の記号がコロン**（下記の表）。`NYSE : AAPL` を通すための副作用 |
| **`BRKーB` / `AAPLーMSFT`（長音符2字）** | **代償ではなく誤りの解消。**日本語 IME でハイフンを打つと出る形 |
| `AAPL0`〜`AAPL9` / `SP500` | 数字。`SP500` → `SP`（実在ティッカー）を止めるための当然の結果 |
| `AAPL※` / `AAPL→` / `AAPL★` / `AAPL•` | 列挙にない非 ASCII 記号。**未知の記号は既定で落ちる**（FR-08 判定基準 4） |
| `AAPL・MSFT` / `AAPL－MSFT` など | 半角版と同じ扱いになるだけ（FR-08「許容した代償の内訳」） |

**空白を挟めば落ちない。ただしコロンだけは例外**（半角・全角とも）。

| 入力 | 結果 | 理由 |
| --- | --- | --- |
| `AAPL - Apple Inc.` / `AAPL & MSFT` / `AAPL ・ MSFT` / `AAPL . Apple` / `AAPL ,` | `us AAPL` | 直後が空白なので分類 2 で通る |
| **`AAPL : MSFT` / `AAPL ： 決算` / `AAPL   :   100` / `AAPL : 232.50`** | **何も返さない** | **本節の境界に到達する前に SPEC-TC-09 が打ち切る。**取引所プレフィックスの区切りが `(\s*[:：]\s*\|\s+)` で、**コロンの前の空白まで飲む**ため、`AAPL` が未登録の取引所トークンとして扱われる（判定基準 7） |

> **この非対称は意図した設計ではなく、`NYSE : AAPL` を通すための副作用。**
> 区切りを `[:：]\s*`（前の空白を飲まない）に狭めれば揃うが、
> **`NYSE : AAPL` → `us AAPL @NYSE` をテストで固定済み**のため、実装を変えると別の担保が崩れる。
> **文書を実装に合わせる側を採った**（ADR-0009 の 12 の追記）。

### 許可列挙のあとに塞いだ3つの穴（記録）

許可列挙（1.15.0）のあと、再レビューで3つの穴が見つかり、いずれも同じバッチで塞いだ。
**規則そのものは変えず、当てはめ方の誤りを直したもの**なので経緯として残す。
判断は [ADR-0009](../adr/0009-exchange-prefixed-symbol.md) の 11・12。

| # | 穴 | 塞ぎ方 | 要件 |
| --- | --- | --- | --- |
| 1 | `\p{L}` に**連結記号の代用**（長音符2字 `ー` `ｰ`）が混ざる | 分類 3 から2字を除く | 判定基準 5 |
| 2 | 許可列挙に `:` を入れたため、**未登録の取引所トークン**が優先順位 4 に落ちて開いていた（`SP:SPX` → SP Plus Corp） | SPEC-TC-09 で、コロン区切りなら**登録の有無にかかわらず打ち切る** | 判定基準 7 |
| 3 | 2 の実装で**全角コロンだけ食い違った**（`A:Z` は止まるが `A：Z` は Agilent を開く） | SPEC-TC-09 の区切りに `：` を含める | 判定基準 5 |

**穴 3 で結果が変わった入力（architect と developer が実コードで検算）。**

| 分類 | 入力 | 以前 | 現行 |
| --- | --- | --- | --- |
| **誤りを止める**（非取引所トークン） | `A：Z` / `AA：B` / `S：SPX` | `us A` / `us AA` / `us S` | 何も返さない |
| 同上（未登録の取引所） | `SP：SPX` / `CME：ES1!` / `XETR：BMW` / `OANDA：EURUSD` | `us SP` ほか | 何も返さない |
| **正しく解釈するようになった**（登録済み） | `NYSE：AAPL` / `TSE：7203` / `TSE：135A` / `NYSE ： AAPL` | `us NYSE` / `us TSE` / `us TSE` / `us NYSE` | `us AAPL @NYSE` / `jp 7203` / `jp 135A` / `us AAPL @NYSE` |
| 同上（以前は何も返さなかった） | `NASDAQ：AAPL` / `TSE_DLY：7203` | — | `us AAPL @NASDAQ` / `jp 7203` |
| 打ち切りの副産物 | `TSE：東証` / `TSE：AAPL` | `us TSE` | 何も返さない（`TSE` は米国ティッカーではない） |
| 代償 | `AAPL：` / `AAPL：100ドル` / `AAPL：決算発表` | `us AAPL` | 何も返さない（半角 `AAPL:` と同型） |

**上記以外は動いていない**（実測）。

| 確認した入力 | 結果 |
| --- | --- |
| 半角コロンの全形（`NYSE:AAPL` / `SP:SPX` / `AAPL:` / `NYSE:AAPL:` / `XETR:BMW`） | 不変 |
| 全角英字（`ＮＹＳＥ：ＡＡＰＬ` / `Ｓ：ＳＰＸ` / `ＡＡＰＬ：`） | 不変（`[A-Z]+` に当たらない） |
| 取引所プレフィックスの後ろの `：`（`NYSE:AAPL：決算` / `TSE:7203：決算`） | 不変（**終止記号として働く**。`：` を分類 4 から外していないことの担保） |
| 日本語の本文・終止記号（`AAPLの株価` / `AAPL、` / `AAPL）` / `AAPL；` / `AAPL！` / `AAPL々`） | 不変 |
| 判定表 (a)〜(f) の全行 | 不変 |
| TradingView 側（`parseExchangeSymbol`） | 不変（`TSE：7203` → `null`。入力に全角コロンは来ない。SPEC-TC-07） |

**穴 1・2 で変わった入力は 17 件**（151 入力で検算）、**穴 3 は上表のとおり**（125 入力で検算）。
いずれも「開かなくなる」方向か「正しく解釈するようになる」方向で、
日本語の本文は 1 件も落ちていない。

### 境界の実装（リテラル3本で同じ値）

> **状態: 一部未実装（予定）。** 差分は「`usCodePattern` の置き場所」だけ
> （`src/service_worker.js` → `src/urls.js` へ移す。FR-28 / ADR-0014 の 3）。
> **式は1文字も変えない。** 境界の値・挙動・下の一致テストの考え方は現行のまま。
> 実装後に architect がこの注記を外す。

| 箇所 | ファイル | 使う経路 |
| --- | --- | --- |
| 優先順位 4 の直書き正規表現（本節） | `src/service_worker.js` | 選択文字列（SPEC-TC-04 の 4） |
| `usCodePattern`（SPEC-TC-09 の `us` 側） | **`src/urls.js`**（1.17.0 で `service_worker.js` から移設） | 選択文字列（SPEC-TC-09）＋ **注入経路（SPEC-TC-10）** |
| `parseExchangeSymbol()`（SPEC-TC-07。TradingView 側。**別担当**） | `src/tradingview-cs.js` | チャート ＋ ウォッチリストの行 |

**リテラルは3本のまま、通る経路は5本になる。**
注入経路（楽天・SBI の4本）は**新しいリテラルを作らず** `usCodePattern` を共有する
（`urls.js` は Service Worker・注入経路・TradingView・オプションページの**すべて**が読み込む）。
判断は [ADR-0014](../adr/0014-us-ticker-in-injection.md) の 3。

```javascript
// 後続境界。3経路で同じ値にする（FR-08 判定基準6）
// 1 終端 / 2 空白 / 3 本文文字（非ASCIIの文字。全角ラテンと長音符2字は除く）/ 4 終止記号（半角・全角）
(?=$|[\s,;:!?"'()[\]{}]|(?![Ａ-Ｚａ-ｚーｰ])(?=[^\x20-\x7E])[\p{L}、。，；：！？＂＇（）［］｛｝「」『』【】〈〉《》〔〕‘’“”])

```

- `usCodePattern`: `/^([A-Z]{1,5})<境界>/u`
- 優先順位 4: `/^\s*([A-Z]{1,5})<境界>\s*/u`
- `parseExchangeSymbol()`: `/^[A-Z]{1,5}<境界>/u`（捕獲グループ無し）

**`usCodeWithExchangePattern`（SPEC-TC-03）の末尾の `(?![A-Za-z])` は変えない。**
そこは**取引所トークン**の境界で、許可列挙にすると `AAPL NASDAQ.` / `AAPL NASDAQ-100` /
`AAPL NASDAQ+` が落ちる（SPEC-TC-09 の判定表 (f) で固定してある）。

> **3経路が一致していることは、規則が正しいことを意味しない。**
> 禁止列挙の時代、3経路は一致していたが**3経路そろって全角の連結記号を素通りしていた**。
> 一致は退行の検知には効くが、規則そのものの誤りは検知しない（FR-08「適用範囲」）。

#### 3経路が揃っていることをテストで固定する

`実装は共有しないが値は揃える`（ADR-0009 の 3・8）は、**これまで人の注意だけで保たれていた。**
1.15.0 で機械的な歯止めを入れた（`tests/service-worker.spec.mjs` の
`米国ティッカーの後続境界: 3経路で同じ値`）。

> **1.17.0 でテストを改訂する（未実装）。** 読むファイルに **`src/urls.js` を足す**。
> 足さないと `usCodePattern` の移設と同時に件数が 3→2 に落ちて失敗する
> （**移設の検知として正しい失敗**。期待値 3 を 2 に下げるのではなく、読む対象を足して直す）。
> あわせてテスト名の「3経路」を**リテラル3本**の意味に改める
> （経路は5本になる。上表と ADR-0014 の 3）。

| 検査 | 何を防ぐか |
| --- | --- |
| **3ファイル**（`urls.js` / `service_worker.js` / `tradingview-cs.js`）から `[A-Z]{1,5}` を含む正規表現リテラルを取り出し、**3件**であること | リテラルの増減（4本目の書き写しが生まれたのに揃え忘れる） |
| 全件に **`u` フラグ**があること | `u` 忘れ（`\p{L}` がリテラルになり、日本語が続く形だけ黙って落ちる） |
| 3件の**境界文字列が完全一致**すること | 片側だけの変更（`NYSE:BRK.B` が経路で結果違いになる） |

> **このテストが示すのは「3経路が同じ」ことだけで、「その値が正しい」ことではない。**
> 規則そのものの誤りは、判定基準 1〜5 のテスト（挙動側）でしか捕まらない。
> **本バッチで3回踏んだのは後者**であり、このテストは**再発の検知**ではなく**退行の検知**に効く。

## SPEC-TC-03 米国銘柄コード + 後置の取引所コード

```text
^\s*([A-Z]{1,5})\s+(<exchanges の 'us' 登録を長い順に並べたもの>)(?![A-Za-z])
```

`TICKER EXCHANGE` の順（例 `AAPL NASDAQ`）。先頭アンカーと後続境界が要る理由は SPEC-TC-02 と同じ。

実装は `src/service_worker.js` の `usCodeWithExchangePattern`。
読み込み時に `exchanges`（SPEC-EL-09）から**1回だけ**組み立てる（1.15.0。ADR-0009 の 4・5）。

| 決め | 理由 |
| --- | --- |
| 区切りは `\s+`（1個以上） | `\s*` だと `AAPLNASDAQ` が通る（FR-14 の弱点表） |
| 取引所の集合は `exchanges` の値が `'us'` のキー6件（`BATS` / `NASDAQ` / `NYSE` / `AMEX` / `CBOE` / `OTC`） | 一覧を正規表現に直書きしない（NFR-13） |
| 選択肢は**長い順**（同長は辞書順）に並べる | 一方が他方の接頭辞になる取引所が後から足されたとき、短い方が先に成立するのを防ぐ。**現在の6件に接頭辞関係は無く、並び順を変えても結果は変わらない**（将来への保険） |

- 1.13.0 からの変更は上の2つ。集合が `(NASDAQ\|NYSE)` の直書き2件から6件に広がったため、`AAPL BATS` などの戻り値に `exchange` が付くようになった（影響は SPEC-TC-05）
- 取引所コードが**前**に付く `EXCHANGE:TICKER` 形式は本規則では扱わない。SPEC-TC-09

- 要件: FR-08, FR-14
- 検証: `auto`（`getTickerCode › 取引所コード付きの米国株を認識する` /
  `後置の取引所コードを exchanges の us 登録6件から判定する`）

## SPEC-TC-09 取引所プレフィックス（`EXCHANGE:TICKER`）

> 1.15.0 で新設（FR-14）。設計判断は [ADR-0009](../adr/0009-exchange-prefixed-symbol.md)。
>

実装: `src/service_worker.js` の `matchExchangePrefixedTicker(text)`。
`getTickerCode()` が優先順位 2（SPEC-TC-04）で呼ぶ。
TradingView のシンボル表記（`NYSE:AAPL` / `TSE:7203`）を選択して右クリックする使い方に対応する。

**戻り値で3つの状態を区別する。**

| 戻り値 | 意味 |
| --- | --- |
| `{ status: true, … }` | 成立。`getTickerCode()` はそのまま返す |
| `{ status: false }` | **打ち切り**。後続の規則を試さない（**コロン区切りで銘柄コードが取れなかった場合と、コロン区切りで取引所が未登録の場合**） |
| `null` | **本規則が不成立**。次の規則（SPEC-TC-03 → SPEC-TC-02）へ送る |

### 形

```text
^\s*([A-Z]+)(_DLY)?(\s*[:：]\s*|\s+)
```

> **半角と全角の両方のコロンを区切りにする**（FR-08 判定基準 5。ADR-0009 の 12）。
> 打ち切りの判定（下記）も同じ2文字を見る必要があり、**判定は `colonSeparatorPattern`
> （`/[:：]/`）という定数に寄せて、2箇所（未登録の分岐／銘柄コードが取れなかった分岐）から
> 参照している。** 片方だけ ASCII コロンで判定すると `A：Z` が素通りするため、
> **式を書き写すのではなく定数を共有する形にした。**

1. 先頭から取引所トークンを取り出す。遅延配信の接尾辞 `_DLY` が付いていれば**剥がす**
2. トークンを `exchanges`（SPEC-EL-09）で引く。値が `'jp'` / `'us'` の**いずれかに一致した場合だけ**
   銘柄コードの抽出へ進む。**未登録のときは区切りで扱いを分ける**（下記「区切り〜」の表。FR-08 判定基準 7）
3. 区切りより後ろから、市場種別ごとに銘柄コードを取り出す

| 市場種別 | 銘柄コードの形 | 戻り値 |
| --- | --- | --- |
| `jp` | `^[0-9][0-9ACDFGHJKLMNPRSTUWXY][0-9][0-9ACDFGHJKLMNPRSTUWXY]` | `{ status: true, type: 'jp', code }` |
| `us` | `^([A-Z]{1,5})<後続境界>`（`usCodePattern`。**境界の値は SPEC-TC-02 が正本**） | `{ status: true, type: 'us', code, exchange }` |

- `exchange` は **`_DLY` を剥がした後**のトークン（`NASDAQ_DLY:AAPL` → `exchange: 'NASDAQ'`）
- `jp` では `exchange` を返さない（SPEC-TC-01 と同じ形。`getUrl` は `jp` で `exchange` を見ない。SPEC-TC-05）
- `us` 側の後続境界は SPEC-TC-02 と同じ（`NASDAQ:ALPHABET` から `ALPHA` を、`NYSE:BRK.B` / `NYSE:BRK-B` / `NYSE:BRK+B` / `NYSE:BRK&B` から `BRK` を切り出さない）。**規則の正本は SPEC-TC-02**
- `jp` 側には後続境界を置かない。SPEC-TC-01 / SPEC-TC-07 と揃える（`TSE:7203A` は `7203`）
- 大文字のみ扱う。`nyse:aapl` は不成立

### 区切りは `:` と空白の両方。ただし失敗したときの扱いが違う

| 区切り | 銘柄コードが取れた | 取れなかった | 取引所が未登録 |
| --- | --- | --- | --- |
| `:` / `：` | その結果を返す | **`{ status: false }`（打ち切り）** | **`{ status: false }`（打ち切り）** |
| 空白 | その結果を返す | `null`（次の規則へ送る） | `null`（次の規則へ送る） |

| 扱いを分ける理由 | |
| --- | --- |
| `:` で打ち切る | 先頭の `NYSE:` は記号表記以外にほぼ現れない。ここで次の規則へ落とすと SPEC-TC-02 が `NYSE` を拾い、**取引所コードそのものを銘柄コードとして返す**（FR-14 が直そうとしている欠陥）に戻る |
| **未登録でも `:` なら打ち切る**（FR-08 判定基準 7） | `X:Y` の形は「取引所:銘柄」の記号表記であって、`X` はティッカーではない。**登録の有無は本拡張の対応範囲の問題であり、`X` がティッカーかどうかとは無関係。**次の規則へ落とすと `SP:SPX`（S&P500 指数の TradingView 表記）が `SP`（SP Plus Corp）を開く。`S&P500` から `S` を切り出さないのと同じ形 |
| 空白は次へ送る | 空白区切りは通常の文と区別できない。取引所コードと同じ綴りの実在ティッカーがある（`CBOE` は Cboe Global Markets の実ティッカー）。`CBOE Global Markets` を選択したときに 1.13.0 と同じ `CBOE` を返すには、後続の規則へ送る必要がある |

**未登録の取引所プレフィックスの実測**（architect。「以前」は判定基準 7 の実装前）。

| 入力 | 以前 | 現行 | 切り出していたもの |
| --- | --- | --- | --- |
| `SP:SPX` | `us SP` | `false` | **SP Plus Corp**（S&P500 指数の TradingView 表記） |
| `CME:ES1!` | `us CME` | `false` | **CME Group** |
| `ICE:BRN1!` | `us ICE` | `false` | **Intercontinental Exchange** |
| `SIX:NESN` | `us SIX` | `false` | **Six Flags** |
| `IDX:BBCA` / `TVC:NI225` / `LSE:VOD` / `OANDA:EURUSD` / `FX:USDJPY` | `us IDX` / `us TVC` / `us LSE` / `us OANDA` / `us FX` | `false` | 指数・海外市場・FX |
| `XETR:BMW` | `us XETR` | `false` | 実在しないティッカー（**この「無害な例」だけを仕様に載せていたため、上の4件を見落とした**） |
| `HTTPS://EXAMPLE.COM` | `us HTTPS` | `false` | 副産物。URL を選択しても開かなくなる |
| **`SP：SPX`（全角コロン）** | `us SP` | `false` | 半角と同じ扱い（判定基準 5。ADR-0009 の 12） |

> **空白区切りは対象外。** `SP 500` / `CME Group` は引き続き `us SP` / `us CME` を返す
> （フォールバックを残さないと `CBOE Global Markets` が落ちる。ADR-0009 の 2）。
> **記号表記かどうかを区別できるのはコロンだけ**という線引きをそのまま延長した。

### 開発中に入った退行（リリース前に修正）

> **1.15.0 のリリース前に潰した欠陥の記録。** 経緯を残すのは、同じ穴をもう一度開けないため。
> 判断は [ADR-0009](../adr/0009-exchange-prefixed-symbol.md) の 7。

**症状:** `NYSE:BRK.B` を選択して右クリックすると `BRK`（**実在する別の銘柄**）のページを開く。

| 実装 | `NYSE:BRK.B` | 害 |
| --- | --- | --- |
| 〜1.13.0 | `us NYSE` | 実在しないティッカー。**開いても無害** |
| SPEC-TC-09 を入れた直後（開発中。**未リリース**） | `us BRK @NYSE` | **実在する別銘柄を開く。**SPEC-TC-02 が「開かないより悪い」と定める失敗そのもの |
| 1.15.0（リリース） | `false` | 何も開かない |

**原因:** 米国ティッカーの後続境界が `(?![A-Za-z])` で、`.` を素通りしていた。
`EXCHANGE:` を剥がして先頭が `BRK.B` になったことで、1.13.0 では届かなかったこの穴に届いた。

> **教訓。** 取り出す位置を1つ前へずらす変更（接頭辞を剥がす）は、
> **それまで到達しなかった入力を既存の正規表現に流し込む**。
> 境界条件は「変えた規則」ではなく「その規則が受け取る入力の集合」で見直す。

**直した内容:** 後続境界に `.` を含めた（`(?![A-Za-z.])`）。
`EXCHANGE:` 経由のときだけ厳しくするのではなく、SPEC-TC-02 と SPEC-TC-09 の**両方**を直した。
理由は ADR-0009 の 7。TradingView 側（SPEC-TC-07）も同じ境界にした。

**この後、同じ穴が `-` `/` `+` `&` にも空いていることが分かり、1.15.0 で4記号まで広げた。
さらに、禁止列挙では未知の文字で開く側に倒れると分かり、規則の向きを許可列挙へ反転した**
（SPEC-TC-02「後続境界は「許可列挙」（FR-08）」と「経緯」。ADR-0009 の 8・9）。
下の「直した箇所」の表は**`.` を足した段階での値**で、現行の値は SPEC-TC-02 を見る。

## SPEC-TC-05 遷移先 URL の選択

`getUrl(type, code, exchange, url1, url2, url3)` の分岐。

| 条件 | 使う URL |
| --- | --- |
| `type === 'jp'` | `url1` |
| `type === 'us'` かつ `url2` あり かつ `exchange` あり | `url2` |
| `type === 'us'` かつ `url3` あり | `url3` |
| 上記以外 | `undefined`（メニューに出さない） |

`url3` を持たないサイトは、米国株のとき `undefined` が返り**タブが開かない**。

> Chrome のコンテキストメニュー自体は `remakeContextMenus()`（SPEC-SW-02）が有効な全キーから
> 静的に作るため、米国株非対応サイトも**項目としては出る**。出ないのはタブだけ。

**`exchange` が実際に URL に出るのは TradingView だけ。**
`url2` に `${exchange}` を含むのは `src/urls.js` の `tradingview.com/chart` の1件で、
残り5件（`us.minkabu` / `us.kabutan` / `finance.yahoo.co.jp` 2件 / `moomoo`）は `url2` と `url3` が同一文字列。
このため 1.15.0 で `exchange` が付く入力が増えても（SPEC-TC-09 / SPEC-TC-03）、
観測できる違いは TradingView の URL が `?symbol=NASDAQ%3AAAPL` の形になることだけ。
`url2` を持つ6件はいずれも `url3` も持つため、`exchange` が付いたことで**開かなくなるサイトは無い**。

`exchange` に渡りうる値は `exchanges` の `'us'` 登録6件（1.13.0 までは `NASDAQ` / `NYSE` の2件）。
`getUrl()` の JSDoc もこれに合わせて `string | undefined` に広げてある（**分岐は変えていない**）。

- 要件: FR-08
- 検証: `manual`（米国株を選択して右クリックし、非対応サイトを選んでも**タブが開かない**こと。チェックリスト D）

## SPEC-TC-06 Content Script での国内コード抽出

楽天・SBI の Content Script は、要素のテキストから国内コードを**非アンカー**で抽出する。

```javascript
/[0-9][0-9ACDFGHJKLMNPRSTUWXY][0-9][0-9ACDFGHJKLMNPRSTUWXY]/
```

- **アンカー無し**（要素テキストの途中にコードがある想定）
- 複数一致した場合は**先頭の1件のみ**使う
- 一致しない要素はスキップする

> **1.17.0 でこの式は変えない（未実装）。** 変えるのは置き場所（4本の Content Script に
> 直書き → `src/urls.js` の `jpLooseCodePattern`）と、**空振りしたときに米国株を試すかどうか**だけ
> （SPEC-TC-10）。**国内株の抽出結果が変わらないことは、この順序で構造的に保証される**
> （FR-28 判定基準 5。ADR-0014 の 2）。**保証は抽出まで。**メニューの出し方は別に2点変わる
> （0件なら出さない／1行1メニュー。SPEC-CS-26 の判定基準表）。
>
> `.match(/…/g)[0]` から `.exec(text)[0]` へ書き換えても結果は同じ（先頭の1件）。
> 共有する正規表現オブジェクトに `g` を付けない（`lastIndex` を持ち回らないため）。

- 要件: FR-02, FR-03, FR-28
- 検証: `auto`（楽天・SBI の注入テスト）

## SPEC-TC-10 注入経路での銘柄コード抽出（国内株・米国株）

> **状態: 未実装（予定）。** 要件は FR-28。実装後に architect がこの注記を外す。

実装: `src/urls.js`（`matchInjectionTicker`）。楽天・SBI の Content Script 4本が共有する。

```javascript
 * @param { string } text 要素のテキスト
 * @param { boolean } allowUs 米国株の抽出を許すか(menuSelectors の us)
 * @returns {{ code: string, type: 'jp' | 'us' } | null}

```

### 判定の順序

| 順 | 判定 | 式 | 戻り値 |
| --- | --- | --- | --- |
| 1 | 国内株（SPEC-TC-06） | `jpLooseCodePattern`（**非アンカー**） | `{ code, type: 'jp' }` |
| 2 | 米国株（`allowUs` が真のときだけ） | `usCodePattern`（**先頭アンカー ＋ 後続境界**。SPEC-TC-02） | `{ code, type: 'us' }` |
| 3 | どちらも不成立 | — | `null` |

- 判定は `text.trim()` に対して行う（現行と同じ）
- **順序を入れ替えない。** 国内株を先に見ることが、FR-28 判定基準 5（国内株の退行を出さない）の
  保証そのもの。米国株の抽出が走るのは**今日の実装が何もしていない要素だけ**になる
- `allowUs` が偽なら 1 と 3 しかない。**今日とバイト単位で同じ結果**
- 取引所は見ない（判定基準 9）。`type: 'us'` に `exchange` は付かず、URL は常に `url3`（SPEC-CS-06）

| 後置の取引所（SPEC-TC-03） | 見る | **見ない**（同上。判定基準 9 で取引所は不要） |
| 米国株の後続境界 | SPEC-TC-02 | **同じ値**（`usCodePattern` を共有する） |

**規則を増やさない側に倒した。** セルの文字列は機械が描いたもので、
取引所付きの表記が現れる根拠が無い。現れると分かった時点で本節に足す。

### 具体例（`allowUs` が真のとき）

| セルのテキスト | 結果 | 理由 |
| --- | --- | --- |
| `7203` | `jp 7203` | 順位 1 |
| `135A` | `jp 135A` | 順位 1 |
| `AAPL` | `us AAPL` | 順位 2（終端） |
| `AAPL アップル` | `us AAPL` | 順位 2（空白） |
| `AAPLの決算` | `us AAPL` | 順位 2（本文文字） |
| **`BRK.B`** | **`null`** | 後続境界に `.` は無い（判定基準 8。`BRK` を開かない） |
| `BRK-B` / `BRK1` / `BRKーB` | `null` | 同上 |
| `ALPHABET` | `null` | 6文字以上 |
| `00700`（中国株） | **`jp 0070`** | **順位 1 が当たる。**この形のセルに届かせないのはセレクタ側の責任（SPEC-CS-26 / ADR-0014 の 4） |
| `USD 米ドル`（預り金） | `us USD` | **同上。**商品種別で走査対象を絞ることで届かせない（判定基準 7） |
| `投資信託` / `トヨタ自動車` | `null` | どちらの式にも当たらない |

> **最後の3行が「抽出だけでは判定基準 6・7 を満たせない」ことの根拠。**
> 抽出は形しか見ない。**どの要素に抽出をかけるかを決めるのはセレクタ**（SPEC-CS-26）。

- 要件: FR-28（判定基準 1・6・7・8・9）、FR-08（後続境界の共有）
- 検証: `auto`（`tests/content-script.spec.mjs`。`evaluateScripts(['src/urls.js'], 'matchInjectionTicker')`
  で上表を直接固定する。ブラウザ不要）／`auto`（フィクスチャでの注入テスト。SPEC-CS-26）

## SPEC-TC-07 TradingView でのコード取得

チャートの `canvas[aria-hidden!="true"]` の `aria-label` から取得する。
`aria-label` は `EXCHANGE:CODE の 1 日 チャート` の形（実測値: `TSE:7203 の 1 日 チャート`）。

> 取引所接頭辞の扱いを 1.10.1 で拡張した。設計判断は [ADR-0002](../adr/0002-tradingview-dom-repair.md) の 2。

### 手順

1. `aria-label` の先頭から `/^([A-Z]+)(_DLY)?:/` で取引所トークンを取り出す
   （`_DLY` は遅延配信の接尾辞。剥がしてから引く）
2. トークンを `exchanges`（SPEC-EL-09）で引き、`'jp'` / `'us'` / 未登録 を判定する
3. 市場ごとに続く銘柄コードを取り出す

   | 市場 | 抽出 | 戻り値 |
   | --- | --- | --- |
   | `jp` | `^[0-9][0-9ACDFGHJKLMNPRSTUWXY][0-9][0-9ACDFGHJKLMNPRSTUWXY]` | `{ code, type: 'jp' }` |
   | `us` | `^[A-Z]{1,5}<後続境界>`（**境界の値は SPEC-TC-02 が正本**。捕獲グループ無し） | `{ code, type: 'us' }` |
   | 未登録の取引所 / `aria-label` 無し / 形が合わない | — | `{ code: null, type: null }` |

   `us` の後続境界は 1.15.0 で追加した（それまでは `^[A-Z]{1,5}`）。
   境界が無いと `NYSE:BRK.B` の行から `BRK`（実在する別銘柄）を返す。
   **取れないときは「何も出さない」に倒す**（`{ code: null, type: null }`。FR-19 / FR-04）。

   **境界の値は Service Worker 側（SPEC-TC-02 / SPEC-TC-09）と揃える**（規則の正本は SPEC-TC-02）。
   FR-08 が「銘柄コードを取り出すすべての経路で結果を一致させる」ことを求めているため
   （`NYSE:BRK.B` / `NYSE:BRK-B` はチャート・ウォッチリストの行・選択文字列のどれでも何も開かない）。
   規則の本体は SPEC-TC-02 の「後続境界は「許可列挙」（FR-08）」、判断は
   [ADR-0009](../adr/0009-exchange-prefixed-symbol.md) の 7・8。
   検証は `tests/content-script.spec.mjs` の `parseExchangeSymbol`。
   `NYSE:BRK.B` / `-` / `/` / `+` / `&` / `_` / `1` / `・` / `ー` / `ｰ` の**10形**が
   `{ code: null, type: null }` になることを固定している
   （ウォッチリストの行がクラス株・数字・中黒で続く形。FR-19 の「何も出さない」側）。
   境界の値が Service Worker 側と同一であることは
   `米国ティッカーの後続境界: 3経路で同じ値` が機械的に固定する（SPEC-TC-02）。

   **FR-08 判定基準 7（未登録の取引所プレフィックス）は本経路では既に満たしている**
   （architect が実測）。`exchanges` で引けなければ `{ code: null, type: null }` を返すため、
   `SP:SPX` / `CME:ES1!` / `ICE:BRN1!` / `SIX:NESN` / `TVC:NI225` / `OANDA:EURUSD` /
   `FX:USDJPY` / `BINANCE:BTCUSDT` / `XETR:BMW` はいずれも何も返さない。
   **Service Worker 側だけが `us SP` を返していた**（SPEC-TC-09。同じ入力が経路で違う結果になる
   ＝ 判定基準 6 違反）。

   長音符2字（`ー` `ｰ`）の除外は本経路にも入っている（境界の値は3経路で同一）。

   > **全角コロンの扱いは本経路と Service Worker 側で違う。** `parseExchangeSymbol()` は
   > `/^([A-Z]+)(_DLY)?:/` で ASCII コロンだけを見る。TradingView の `aria-label` と行の属性値は
   > **機械生成で全角コロンを含まない**ため（実測: `TSE:7203 …` / `BATS:AAPL …`。
   > `TSE：7203` は本経路では `null` のまま）。
   > **入力が違うので規則が違ってよい例**であり、後続境界（`usCodePattern` 相当）の値は揃えている。

### 旧との差分

| | 旧（〜1.10.0） | 新（1.10.1〜） |
| --- | --- | --- |
| `jp` の接頭辞 | `TSE:` / `TSE_DLY:` を直書き | `exchanges` の `jp` 登録 ＋ `_DLY` 剥がし |
| `us` の接頭辞 | **`BATS:` のみ** | `exchanges` の `us` 登録（`BATS` / `NASDAQ` / `NYSE` / `AMEX` / `CBOE` / `OTC`） |
| 利用者 | 「株Link」ボタン（SPEC-CS-12）のみ | ボタン ＋ **右クリックメニュー（SPEC-CS-11）** |
| canvas の選び方 | 最初にヒットした1件 | 変更なし（複数チャートでは左上のチャートになる。SPEC-CS-11 の既知の制限） |

拡張理由: 右クリックメニューの銘柄取得をここに一本化したため（SPEC-CS-11）。
ログイン済みで `NASDAQ:` / `NYSE:` のまま表示される場合に `BATS:` 限定では取れない。

### 未ログイン時の TradingView の挙動（2026-08-23 実測）

| URL で指定した銘柄 | `aria-label` |
| --- | --- |
| `TSE:7203` | `TSE:7203 …`（遅延配信時は `TSE_DLY:7203 …`） |
| `NASDAQ:AAPL` | **`BATS:AAPL …`** |
| `NYSE:IBM` | **`BATS:IBM …`** |

**未ログインでは米国株の提供元が BATS に置き換わる。** 旧実装が `BATS:` だけで足りていたのはこのため。
ログイン済み（特に有料データ契約あり）で `NASDAQ:` / `NYSE:` のまま出るかは**未確認**。
`exchanges` に両方を登録してあるため、どちらの表記でも銘柄コードを取得できる。

> `code: null` のとき、ボタンは隠れ（SPEC-CS-12）、右クリックメニューは変更されない（SPEC-CS-11）。
> **エラーは出さない。**
>
> **Service Worker 側の `matchExchangePrefixedTicker(text)`（SPEC-TC-09）とは別実装のまま置いた**（1.15.0）。
> 入力が違う（機械生成の `aria-label` ／ 利用者が選んだ任意の文字列）ため、規則が次のように分かれる。
>
> | | TradingView 側（本節） | Service Worker 側（SPEC-TC-09） |
> | --- | --- | --- |
> | 区切り | `:` のみ | `:` と空白 |
> | 失敗時 | 常に「何も出さない」 | コロンは打ち切り、空白は次の規則へ送る |
> | 戻り値 | `{ code, type }`（`null` 埋め） | `{ status, type, code, exchange }` / `null` |
> | ティッカーの後続境界 | SPEC-TC-02 の許可列挙 | 同じ値（**揃える**。FR-08 の適用範囲） |
>
> **後続境界だけは揃える。**「別銘柄を開かない」は入力の出所に関係なく守る一線で、
> ここが版ごとにずれると同じ `BRK.B` が経路によって別の結果になる（ADR-0009 の 7）。
> 共有するのは `exchanges` の表だけで、解析器そのものは共有しない（ADR-0009 の 3）。
>
> このため **`_DLY` を剥がす処理は TradingView 側（本節）と Service Worker 側（SPEC-TC-09）の
> 2箇所にある**。表 `exchanges` は1箇所のままで、`_DLY` 付きのキーを表に載せないことは
> SPEC-EL-09 の自動テストが固定している。**残る重複は「接尾辞を剥がす」という手順そのものだけ。**
>
> TradingView 側の解釈は FR-19 でウォッチリストの行とも共有するため関数に切り出してある
> （呼び先は SPEC-CS-23。**本節の手順 1〜3 は変わらない**）。
> それを `src/urls.js` へ上げて Service Worker と共有するかは ADR-0009 の 3 の判断に属し、
> **1.15.0 では上げていない**（入力の性質が違い、失敗時の扱いと戻り値の形が異なるため）。
>
> サイト側 DOM に強く依存する。TradingView の改修で無言のうちに壊れる。

- 要件: FR-04
- 検証: `auto`（表そのものは SPEC-EL-09 の `urls.js: exchanges` で検査。
  `aria-label` の解析自体は TradingView 上でしか動かないため自動テスト対象外）／
  `半自動`（`npm run check:selectors -- --only=tradingview` の `chart-canvas` と
  `tv-symbol` 追加検査。SPEC-SC-11）／
  `manual`（`docs/MANUAL-CHECKLIST.md` A-1 / A-7。TradingView にログインして `NASDAQ:AAPL` でも
  「株Link」ボタンが出ること）
